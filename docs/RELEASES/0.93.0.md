# Axiom 0.93.0

**Released:** 17 November 2026

## Setup no longer crashes when the global guard is inaccessible

The main-push packaging check failed with an unhandled exception:

```
Unhandled exception. System.UnauthorizedAccessException:
Access to the path 'Global\AxiomSetup.SingleInstance' is denied.
```

The single-instance guard opened the global mutex directly. When another setup instance (or a
previous run in a different session) owns it with an access-control list this account cannot open,
`new Mutex(...)` throws and the installer aborts before it can even print the permission or safety
messages. Silent installs on shared and service accounts can hit the same state.

- Setup now falls back to a session-local `Local\AxiomSetup.SingleInstance` guard when the global
  one is inaccessible, writes a short note to stderr, and continues.
- If the fallback guard is also already owned, setup still exits with the existing
  "already running" message and code 3.

## Verification

- `dotnet build Axiom.sln -c Release` — 0 warnings, 0 errors.
- The setup CLI guard (`--silent` without `--accept-risk` → exit 2) and the packaging check pass on
  the Windows runner; the `main` push workflow after this merge is green.
