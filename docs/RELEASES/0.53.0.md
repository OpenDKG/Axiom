# Axiom 0.53.0

**Released:** 15 November 2026

0.53.0 fixes the service-image upgrade that failed on a Windows 11 machine upgrading from 0.30.0,
and makes such failures explain themselves instead of ending as an unexplained exit code.

## The failure (issue #367)

Live upgrade log in the lab VM:

```
[00:02] Complete protection: registering the Axiom Windows service (one elevation prompt).
[01:03] The elevated service installer exited with code 7.
```

`C:\Program Files\Axiom\Service\Axiom.Service.exe` stayed at **0.30.0.0** while the per-user install
was already 0.51.0. The Application log at the same time showed the 0.30 service crashing
(`System.OperationCanceledException`, 0xe0434352) and SCM event 7023. Its recovery action is
`restart/5000`, so SCM restarted the old image while the installer was replacing it: the file stayed
mapped, `CopyWithRetry` exhausted its ten attempts, and `ServiceInstaller.Install` returned **7**
(`The service image could not be protected`).

## What changed

- **Recovery actions are cleared before the stop.** `ServiceInstaller` runs
  `sc failure Axiom reset= 0 actions= ""` before `StopExisting`, waits up to 45 s for `Stopped`, then
  restores `failure ... restart/5000` on the new service. A crash-looping predecessor can no longer
  re-map the image mid-upgrade. Uninstall clears them too.
- **Copy retries for 30 s and reports every blocked attempt** instead of failing after ten silent
  seconds.
- **`sc` timeouts no longer crash the elevated installer.** `RunSc` previously read `ExitCode` after
  a 30 s wait even when the process was still alive, which throws `InvalidOperationException`; it now
  kills the child and reports `1460` (ERROR_TIMEOUT). The same applies to `sc start` on a service
  that reports `Start Pending`.
- **The elevated process writes its own step log.**
  `%ProgramData%\Axiom\logs\service-install.log` records source/target, stop status, copy retries,
  hash verification and the exact failure. It is capped at 256 KB with the last 200 lines kept.
- **Setup shows the reason.** When the service installer exits non-zero, the setup log now prints the
  tail of that file after `exited with code N`.
- **Complete Setup & Optional Modules (issue #364).**
  - Replaced the unsupported `oxigraph-worker` fallback with `'auto'` in `OptionalModuleInstaller` so Blackbox setup no longer exits `1` when VC++ 2015–2022 Redistributable is absent.
  - Added `npm` pre-flight detection (`ResolveNpmExecutable` / `Get-Command npm`) before invoking `npm ci` for DKG installation.
  - Added existing-install detection (`Upgrade Axiom`), `Partial Success` reporting when core Axiom installs and optional modules warn, and `Open Axiom`, `Repair`, and `Uninstall` actions (`--uninstall`) in `Axiom.Setup`.
- **Dashboard usability & Copy / End scope clarity (issue #365).**
  - Converted header, status bar, and table row cells to `AxiomSelectableTextBlock`, added explicit `Copy row` / `Copy local` / `Copy remote` / `Copy details` / `Copy status` actions, disambiguated `End process (PID)` vs `End application`, and removed the redundant top-right `LOCAL-FIRST` badge.

## Verification

- Full `Axiom.sln` Release suite passed (1,110/1,110 across 9 test projects, 0 failed, 0 skipped), `Axiom.Portable.slnx` built cleanly (`0 Warning(s), 0 Error(s)`), and `Windows CI` (run `43734521528`) passed `Build, Analyze & Test (Windows)` and `Setup Packaging & Safe CLI Check` on merged `main`.
- New `ServiceInstallLogTests`, `OptionalModuleInstallerTests`, `OptionalModuleInstallerScriptTests`, and `DashboardUsabilityTests` cover service log tails, `'auto'` / `npm` checks, and dashboard copy/scope behavior.

## Notes

- The machine-wide service still needs one UAC prompt; an unattended `--silent` install cannot answer
  it, so the lab verifies the per-user/partial path unattended and the service upgrade with one
  approval.
- The old service's `OperationCanceledException` crash is 0.30.0 behavior; 0.53.0 replaces that image
  rather than reusing it.
