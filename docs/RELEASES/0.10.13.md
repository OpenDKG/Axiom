# Axiom 0.10.13

**Release date:** 2026-11-10

Antigravity is now a protected harness. Axiom installs a `PreToolUse` hook through Antigravity's own
`hooks.json` format, so its tool calls reach the Blackbox guard and appear as `antigravity` evidence.

## How it works

- Antigravity reads global hooks from `~/.gemini/config/hooks.json`. Axiom adds one entry named
  `axiom-guard` with a `PreToolUse` handler matching every tool (`"matcher": "*"`).
- The handler runs `axiom-antigravity-hook.py`, which takes Antigravity's payload
  (`toolCall.name`, `toolCall.args`, `conversationId`, `stepIdx`), calls the shared Blackbox bridge,
  and translates its result into Antigravity's output shape:
  - `{"decision": "allow"}` when the guard allows,
  - `{"decision": "deny", "reason": ...}` when the guard blocks.
- The user's existing `hooks.json` keys and other hook definitions are preserved; only the
  `axiom-guard` key is written.
- The Agents page lists Antigravity as a protected harness once the hook is installed and reports
  when it was observed at runtime. Detection is by the Antigravity install path or `~/.gemini`.

## Limits

- Only `PreToolUse` is wired. Session start/stop and model-invocation events are not recorded for
  Antigravity yet.
- The hook fails open if the bridge or guard throws, consistent with the other Axiom hooks.
- Antigravity reads hooks at start: restart it after installing or repairing the hook.
- A deny is a hard block per Antigravity's hook contract; an allow still depends on Antigravity's own
  permission policy.

## Verification

- `dotnet build Axiom.sln -c Release`: 0 warnings, 0 errors.
- `dotnet test Axiom.sln -c Release`: 500 passed, 0 failed.
- Local install wrote `~/.gemini/config/hooks.json` with the `axiom-guard` entry and the wrapper
  script under `%LOCALAPPDATA%\Axiom\modules\blackbox\agent-blackbox\`.
- End-to-end: a sample `PreToolUse` payload ran the wrapper, returned `{"decision": "allow"}` and
  appended an `antigravity` `GUARD_ALLOWED` evidence row (tool `run_command`).
- Existing hooks.json content is merged; the installer leaves unknown keys untouched.
