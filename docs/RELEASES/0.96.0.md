# Axiom 0.96.0

**Released:** 17 November 2026

## Setup no longer aborts when both single-instance guards are inaccessible

0.93.0 added a session-local fallback for the global setup mutex. The main-push packaging check
still failed, now on the fallback itself:

```
Unhandled exception. System.UnauthorizedAccessException:
Access to the path 'Local\AxiomSetup.SingleInstance' is denied.
```

Two setup checks started at the same time on the shared runner create the session mutex with an
access-control list the other account cannot open, so the fallback threw as well.

- Setup now tries the global guard, then the session guard, and if both are inaccessible it writes
  a short note and continues with an unnamed mutex (no single-instance guard for that run).
- Losing the guard in that rare ACL state is better than aborting an unattended install or the
  packaging check with an unhandled exception. When the guard is available, a real second instance
  still exits with the existing message and code 3.
- The CLI consent gate is unchanged: `--silent` without `--accept-risk` exits with code 2.

## Verification
