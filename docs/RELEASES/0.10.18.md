# Axiom 0.10.18

**Release date:** 2026-11-10

AI Analyst indicators are now taken only from a structured field and must match evidence Axiom
collected itself. Prose is never scanned, so the model cannot introduce a domain, URL or address
that Axiom did not observe.

## What was wrong

`ThreatShareIocExtractor` searched the finding's summary, observations, evidence references and
recommended actions for URLs, domains, IPv4 addresses and SHA-256 strings, and queued every match as
`malware-delivery`. That produced false positives from benign comparisons ("unlike its usual
traffic to registry.npmjs.org"), from version strings in recommendations ("block 1.0.0.1") and from
file names ("agent.py"), and it let attacker-controlled command-line text steer a model into naming
a victim domain. Nothing checked that the value had actually been observed.

## What changed

- `AiFinding` has a structured `indicators` array: `type` (domain, url, ip, hash), `value` and
  `role`. The analyst prompt asks for it and forbids values that are not in the supplied evidence.
- `ThreatShareIocExtractor` reads only that array, only entries with `role: malicious` from a
  `SUSPICIOUS`/`SUPPORTED_ALERT` finding at high or critical severity, and only values that match a
  remote endpoint (or a hostname endpoint) present in the evidence package. The evidence package is
  now passed from the analysis path; without it, nothing is proposed.
- Summary, observations, evidence references and recommended actions are no longer inspected.
  Benign comparisons, recommendations and version-like strings cannot become candidates.
- Hash indicators are rejected while the evidence package contains no hash Axiom computed. The
  collection point is marked so hashes can be enabled when the evidence carries them.
- Duplicate and private/loopback values are still filtered by the existing normalizer.

## Limits

- The Blackbox report still uses the closest available context label (`in-tool-output`) and the
  `malware-delivery` reason. A dedicated "observed endpoint" context should come from Umanitek;
  Axiom does not invent an unsupported vocabulary value.
- Severity stays `high` for now because that is the reporter's supported floor. The evidence match,
  not the model's label, is what makes the candidate eligible.
- A model can still label an observed, legitimate endpoint as malicious. It appears in the review
  queue with the value and the source, and nothing is sent until the user presses Share or Send now.

## Verification

- `dotnet build Axiom.sln -c Release`: 0 warnings, 0 errors.
- `dotnet test Axiom.sln -c Release`: 517 passed, 0 failed. `ThreatShareIocExtractorTests` now
  covers observed vs unobserved values, prose-only findings, role filtering, severity/status gates,
  private remotes, and the missing-evidence path.
- No provider request and no report submission were made during verification.
