# Axiom 0.12.0

**Release date:** 2026-11-12

This release consolidates the service-owned network recovery work, the first agent-enforcement
foundation, the Avalonia UI polish and the supporting ADRs/tracker. It remains a Windows-first
development release; core protection is local-first and does not require Blackbox, DKG or an AI
provider.

## Highlights

### Network recovery is service-owned

- The elevated Axiom service captures DNS and Axiom-owned firewall state into
  `%ProgramData%\Axiom\network-recovery.txt` before the local pipe server starts.
- The snapshot is versioned, checksummed and strictly validated. Missing, corrupt, unreadable and
  valid-empty states are distinct; a corrupt baseline is never silently replaced.
- Restore reads only the validated snapshot, applies IPv4/IPv6 DNS per adapter (DHCP reset or exact
  static servers), and removes only captured `Axiom::{id}::{OUT|IN}` rules after re-checking the OS
  ownership group/description. Every changed item is read back.
- Capture and restore are serialised and idempotent. Repeated restore treats an already-absent rule
  as verified absence; an interrupted restore keeps the baseline for a safe retry.
- The service watchdog treats a running loopback resolver as intentional, restarts a stopped one,
  and only after that rolls back DNS. It never removes firewall rules and is not driven by the
  desktop lifecycle.
- An explicit elevated `Axiom.Service.exe --recover-network --apply` path exists for a stopped
  service; the default invocation is a dry-run plan.
- The desktop sends typed capture/restore commands over the authenticated local pipe and reports
  unavailable, unauthorized, incompatible, busy, missing, corrupt and partial outcomes truthfully.

### Agent enforcement foundation

- Threat-share URL paths are rejected by default (B2).
- Module endpoints must prove their owning process before receiving privileged settings (B3).
- Ambiguous reporter outcomes stay unverified and are not retried automatically (B4).
- Added the E0 host capability matrix, the E1 deterministic offline policy engine, E2 host
  hook-event/deny-payload mapping and the E5 cooperative enforcement status surface.
- These slices are deliberately non-autonomous: no hook script enables enforcement, no model or
  DKG reputation can authorize a block, and no live publication is added.

### UI and documentation

- Avalonia navigation, card surfaces, active theme/effects toggles and the session context menu were
  polished, with tests for the active-state flags.
- Added enforcement baseline/capability ADRs, the enforcement tracker, leadership titles, and the
  network-recovery runbook/ADR.

## Verification

- `dotnet build Axiom.sln`: 0 warnings, 0 errors.
- `dotnet test Axiom.sln`: 717 passed, 0 failed across all test projects.
- Read-only host check: DNS capture returns valid per-family DHCP/static states; no network change
  was applied while validating capture.
- Release artifacts are built by `scripts/build-release.ps1`; checksums are published in
  `SHA256SUMS.txt`.

### Not verified in this release

- A live/elevated restore that actually changes adapter DNS or removes a real `Axiom::` firewall
  rule.
- Installation/start of the Windows service plus the elevated offline `--apply` command.
- A live resolver failure/restart cycle under the service watchdog.
- The full Windows 10/11 VM matrix for Privacy Shield and enforcement (VPN/split-DNS, sleep/wake,
  port 53 conflicts, uninstall/recovery).

These remain explicit verification gates; the release does not claim they passed.

## Compatibility and rollback

- Windows 11 x64 is the primary target; Windows 10 x64 is best-effort.
- Portable desktop/service are self-contained; no .NET runtime is required.
- The timeout/network-recovery snapshot is inert data. To roll back the application, stop the
  service, deploy the previous build and start it again. Do not remove firewall rules by prefix and
  do not delete the history database as a rollback step.
- The portable artifacts are **unsigned**; Windows SmartScreen may warn. Verify the published
  `SHA256SUMS.txt` and compare it with the release assets. #119 tracks signing and SmartScreen
  reputation.
- Linux and macOS are not part of this release.
