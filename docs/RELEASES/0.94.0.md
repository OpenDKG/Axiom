# Axiom 0.94.0

**Released:** 17 November 2026

## DNS is a choice again, with plain-language explanations (issue #366)

Privacy Shield previously offered one upstream box and a DoH switch. The page now starts with a
**Resolver choice** list; each entry states what it does and what changes on the network adapter:

- **Automatic - Axiom's encrypted resolver (recommended).** Axiom forwards to its built-in encrypted
  DoH resolver; the upstream field stays empty.
- **Security-focused - Cloudflare 1.1.1.1.** Forwards DNS to Cloudflare over encrypted DoH
  (`1.1.1.1, 1.0.0.1`), so queries leave the machine to Cloudflare.
- **Custom upstream.** Keeps the upstream list and DoH switch under manual control.

Every entry repeats the same boundary: the adapter is only changed when **Auto-point adapter DNS**
is enabled, and that switch lives in the Adapter DNS card below. Selecting a preset fills the
upstream fields; it does not silently apply adapter changes. Existing settings map back onto the
matching choice when the page loads.

## Configure the AI Analyst from an agent that is already signed in (issue #366)

The AI Analyst settings card now carries a **Copy setup prompt** button. It copies a one-line
instruction the user can send to an agent that is already running locally:

> Configure Axiom's AI Analyst to use this agent's own local login instead of a separate API key:
> open Axiom > AI Analyst, set Provider to OpenChamber Local, keep the local endpoint
> (opencode://local), choose this session's model, save the settings, then run one test analysis and
> report the exact settings you changed. Do not paste an API key into this prompt.

The prompt reuses the agent's own local login through the OpenChamber / OpenCode provider, so no
second API key is needed. The manual provider, endpoint, model and key fields stay available.

## Verification
