# Axiom 0.97.0

**Released:** 17 November 2026

## The VM enforcement canary now proves a real deny and rollback

`scripts/validate-vm-enforcement.ps1` has been used to validate OS enforcement since the early
phases, but on the current Windows 11 build its live mode did not prove anything:

- It ran the canary over loopback (`127.0.0.2` / `127.0.0.3`). Windows Firewall exempts loopback
  traffic, so the temporary block rule was created and read back, yet the connection still
  succeeded (`blocked=True`). A loopback canary can never demonstrate an OS deny on this platform.
- It copied `powershell.exe` to `%TEMP%\pwsh-canary.exe` and ran the copy. The renamed copy did
  not run reliably in the VM, so even the baseline failed.

The live mode now:

1. Connects to a **remote** endpoint (default `1.1.1.1:443`, overridable with `-RemoteHost` and
   `-RemotePort`) and refuses loopback targets with an explicit message.
2. Blocks the **real** target program by path (default: the running PowerShell executable, or
   `-TargetProgram`) for that endpoint only.
3. Reads the rule back (Block, enabled, Outbound), proves the connection is denied, removes the
   rule, proves connectivity returns, and checks that no canary rule remains.
4. Cleans up in a `finally` block on any failure.

## Live result in the isolated VM

```
[1/5] Verifying baseline connectivity to 1.1.1.1:443...        reachable=True
[2/5] Creating temporary rule Axiom-VM-Validation-Canary...
[3/5] Verifying the rule read-back...                           action=Block enabled=True direction=Outbound
[4/5] Verifying the connection is denied...                     reachable=False
[5/5] Rolling back and verifying connectivity is restored...    reachable=True, rules_remaining=0
RESULT: OS_DENY_VERIFIED (block, read-back and rollback on 1.1.1.1:443)
```

This validates that the OS firewall can deny and roll back for one program and endpoint. It does
not enable Axiom's own WFP path: `enforcement.status` still reports zero host/OS deny receipts and
the app keeps describing enforcement as hook-level.

The dry-run stays non-mutating and is the default.

## Verification

- `dotnet build Axiom.sln -c Release` — 0 warnings, 0 errors.
- The rewritten script ran elevated in the VM: OS_DENY_VERIFIED, zero leftover rules.
- Windows CI build, tests and packaging check pass; 0.97.0 installed on host and in the VM.
