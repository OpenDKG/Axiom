# Axiom 0.10.10

**Release date:** 2026-11-10

A dashboard that answers its API but receives no events no longer looks like a frozen Axiom page.

## What changed

- The Overview **Agent activity** card now shows the age of the newest recorded event, for example
  `Newest agent event 14:59 (6h 30m ago).`
- After **15 minutes** without a new event the line turns amber and says what to check: the Blackbox
  dashboard may be stalled, or the agent hooks are not loaded. It points at **Install/repair agent
  hooks** on the Agents page and at restarting the agent.
- The freshness line updates with the existing 15-second refresh, so a dashboard that recovers
  returns to the muted text without a page reload.
- No behaviour change to the dashboard, hooks or history; this release only stops Axiom from
  presenting old data as if it were live.

## Why

The dashboard can keep serving `/api/audit` while nothing new is appended (for example when an
OpenCode plugin loses its event stream or hooks are not loaded in a restarted agent). Axiom showed
the last event with no timestamp, which read as “stuck”. The event age makes the difference between
“no traffic” and “no feed” explicit.

## Verification

- `dotnet build Axiom.sln -c Release`: 0 warnings, 0 errors.
- `dotnet test Axiom.sln -c Release --no-build`: 496 passed, 0 failed.
- New tests: fresh event is not stale; an old event produces the amber text with the age and the
  repair hint; missing history is reported without a timestamp.
- Live check while the audit feed was stale: the card showed the last event age in amber.
