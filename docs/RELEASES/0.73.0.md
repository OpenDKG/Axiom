# Axiom 0.73.0

**Released:** 16 November 2026

## Guard

Batch 13 probed wildcard spellings of protected and credential paths on the 0.72 hooks (issue #401).

Found and fixed:

| Probe | Payload | Now |
| --- | --- | --- |
| SSH key | `.ss?\id_rsa`, `.ss*\id_rsa`, `[.]ssh\id_rsa` | protected-path block |
| AWS credentials | `.aws\credential?` | credential-store block |
| kubeconfig | `.kube\conf?g` | credential-store block |
| KeePass file | `vault.kdb?` | credential-store block |
| Browser login DB | `...\Chrome\User Data\*\Login Data` | credential-store block |

Every check compared literal text, so a wildcard (`?`, `*`, `[...]`) never matched the name it
resolves to. `_glob_hits` now translates the wildcard window into a regex and matches it against the
protected token or store marker, and all three checks — `_reads_protected`, `_hits_protected` and
`_sensitive_store` — use it. Only windows around a wildcard are tested, so long tool arguments stay
cheap.

Batch re-verified **10/10**; controls (`dir C:\Lab\*.md`, `notes.txt`, `kdbx-notes.md`) still allow
and batches 1-12 stay clean.

## DeepSeek

`DeepSeekProtection` no longer reports DSH as protected from the presence of the bridge package alone
(issue #369). It reads the bridge and runtime `package.json` versions and requires the pairing to
match — `dsh plugin add` rejects a bridge built for another runtime — and surfaces a Node engine
warning when the installed Node is below the runtime's `engines.node` floor. Both shells (Windows and
Avalonia) show the mismatch or the Node warning in the agent row.
