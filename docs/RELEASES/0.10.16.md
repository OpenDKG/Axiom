# Axiom 0.10.16

**Release date:** 2026-11-10

User-visible punctuation that the UI showed as `?` is repaired in the Privacy Shield and Agents
pages, and in two documents that carried the same damage.

## What was wrong

An earlier encoding conversion wrote U+FFFD (the Unicode replacement character) over characters it
could not represent. The Winsider/WPF-era text handling turned those into visible question marks:

- the Privacy Shield adapter list read `Ethernet 2 ? default route ? DNS 127.0.0.1 ? Privacy Shield`,
- the page subtitle, DNS profile names, the blocked-history summary and the resolver detail line
  used `?` where a middle dot belonged,
- the Agents page used `?` in 49 places: separators in activity totals, threat-sharing status,
  verified-sync counts, protection-test results and the truncated-evidence marker.

The README and `docs/AVALONIA_MIGRATION_BASELINE.md` also contained double-encoded text: `â€”` instead
of `—`, `Ã—` instead of `×`, and a corrupted architecture diagram.

## What changed

- Restored the intended characters from the last undamaged revisions: em dash (`—`), middle dot
  (`·`), ellipsis (`…`), multiplication sign (`×`), arrow (`→`), heart (`♥`), and the box-drawing
  characters in the README diagram.
- Repaired the two Markdown files with a reversible CP1252-to-UTF-8 pass that only rewrites runs
  which decode as valid UTF-8, leaving normal prose untouched.
- Added no behaviour change: the strings and their separators are the only difference.

## Verification

- `dotnet build Axiom.sln -c Release`: 0 warnings, 0 errors.
- `dotnet test Axiom.sln -c Release`: all tests pass.
- Scanned every source, test, document, script and project file for U+FFFD and for the byte
  patterns of double-encoded UTF-8: none remain.
- Live UI after install: the adapter row reads
  `Ethernet 2 — default route · DNS 127.0.0.1 · Privacy Shield, 192.168.0.1` and the page subtitle
  uses `·`.
