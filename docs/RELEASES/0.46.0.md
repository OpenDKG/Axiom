# Axiom 0.46.0

**Released:** 15 November 2026

0.46.0 comes from the first **live Codex sweep**: Codex CLI 0.169.0 was installed in the lab VM,
Axiom provisioned `~/.codex/hooks.json`, and the same vector families used for OpenCode were run
through the Codex hook.

## What the live sweep found

| Hook under test | Result |
| --- | --- |
| Installed 0.30.0 Codex hook | 4/15 (controls, literal `.ssh`, wallet keystore) |
| 0.45.0 generated Codex hook | 14/15 |
| 0.46.0 generated Codex hook | **15/15** |

The one remaining gap in 0.45.0 was a real bug: `_check_command_safety` returned early when the
tool call had no command string, so a `read_file`-style call with only `path`/`filePath` never
reached `_sensitive_store`. `.git-credentials` was readable through Codex even though the store
detector existed.

## Fix

- `_check_command_safety` now evaluates the credential-store check **before** the "no command"
  early return, using `command` or the `path`/`filePath` argument. Other host adapters that use the
  shared helper (Claude, Antigravity, Cursor, Windsurf, Gemini, Cline, Copilot, DeepSeek, ZCode)
  get the same correction.
- The behavioural Python test now asserts three `_check_command_safety` cases: a credential-store
  path is blocked, a benign path and a benign command are not.

## Verification

- Codex live vectors with the 0.46.0 generated hook: **15/15** (controls allow; `$HOME`, `\\?\`,
  move, takeown, upload, `reg save SAM`, procdump lsass, `sc create`, Register-ScheduledTask,
  `.git-credentials`, wallet keystore and injection all block).
- `dotnet build Axiom.sln -c Release` — 0 warnings, 0 errors.
- `dotnet test Axiom.sln -c Release --no-build -m:1` — full suite in the release run.
- Installed-build verification still waits for the owner's upgrade; the live Codex test used the
  generated 0.46.0 hook from a temp path, not an installed file.

## Upgrade notes

Install over 0.45.0. After the upgrade, restart the desktop once so it reprovisions
`~/.codex/hooks.json` and the shared hook script.
