# Axiom 0.10.17

**Release date:** 2026-11-10

Threat sharing no longer sends indicators on a timer while the page says they are waiting for
review.

## What was wrong

`AgentsPageViewModel.ApplyThreatShareStatus` started a submission whenever sharing was on, at
least one indicator was pending and a minute had passed since the last attempt. The same page
called the queue "waiting for review" and offered **Dismiss**, but there was no real review step:
a report could be signed with the user's reporter key and published to the shared DKG graph before
the user saw it. Once published, it is replicated and cannot be taken back.

## What changed

- Automatic submission is removed. `Share` on a single queued indicator and `Send now` for the
  reviewed queue are the only paths that run the Blackbox reporter.
- Both paths go through the same bounded submit routine; `Share` reuses the daily-cap guard.
- The queue text now says *"waiting for your review … nothing is sent until you press Share or
  Send now"* while sharing is on, and *"nothing is signed or sent"* while it is off.
- The service's queue detail and `docs/INTEGRATIONS.md` describe the same behaviour.
- The card copy no longer claims that sharing is what sends: sharing enables the feature, the user
  sends the report.

## Limits

- `Send now` shares every pending indicator up to the daily cap, not only the visible first eight.
  Use per-item **Share** and **Dismiss** to curate.
- A report that Blackbox refuses is still recorded as rejected; retry handling for transient
  failures is tracked separately (issue #224).

## Verification

- `dotnet build Axiom.sln -c Release`: 0 warnings, 0 errors.
- `dotnet test Axiom.sln -c Release`: 512 passed, 0 failed.
- Manual: with sharing off, the card reports that nothing is signed or sent and both share
  actions are disabled. No report was submitted during verification.
