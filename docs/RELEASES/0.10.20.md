# Axiom 0.10.20

**Release date:** 2026-11-11

A transient reporter failure no longer throws an indicator away, and the daily cap no longer
consumes one. The queue keeps the candidate, counts the attempt and sets a retry time.

## What was wrong

Every failed reporter call was recorded as `ThreatShareState.Rejected`, and `_knownIds` prevented
the same indicator from being queued again. A timeout, the Blackbox DKG node being offline, a
missing Hermes CLI or the reporter's daily cap therefore lost the candidate permanently. The daily
cap was worse: the capped item was recorded as rejected before the loop stopped.

## What changed

- `ThreatShareState.Deferred` holds a transient failure. The service increments `Attempts`, keeps
  the item in the queue and stores `NextAttemptUtc` with a 5-minute backoff that doubles per attempt
  up to 6 hours.
- `ThreatShareRecordRequest.Deferred` lets the desktop tell the service that a failure may succeed
  later. `Rejected` is now recorded only when the desktop classifies an explicit schema or policy
  refusal.
- `ThreatShareCli.ReportAsync` returns a status instead of a bare boolean:
  `Shared`, `AlreadyShared`, `CapReached`, `Rejected` or `RetryableFailure`. Missing CLI, timeout,
  process errors and unknown output are retryable; known refusal wording is rejected.
- `CapReached` never calls the record path, so the capped indicator stays pending for the next day.
  The action text says the remaining indicators stay queued.
- The Agents page lists deferred items with their attempt state and retry time (local clock), and
  `Share`/`Send now` skip a deferred item until its backoff has passed.
- `docs/INTEGRATIONS.md` states the same behaviour.

## Limits

- `hermes blackbox report` still has no documented machine-readable output. Classification is based
  on its prose: explicit success/cap lines, a small refusal vocabulary, and "retry" for everything
  else. If the reporter changes its wording, unknown failures degrade to a deferred retry rather
  than losing data.
- A permanently refused value that does not match the refusal vocabulary is retried with backoff
  until the user dismisses it. It is never silently dropped.
- Backoff is advisory for the queue: `Send now` retries due items only, but the user can still open
  a deferred item and press its `Share` after the retry time.

## Verification

- `dotnet build Axiom.sln -c Release`: 0 warnings, 0 errors.
- `dotnet test Axiom.sln -c Release`: 552 passed, 0 failed. New service tests cover deferred
  persistence and attempt counting, dismissal of a deferred item, and explicit rejection.
- No reporter call or report submission was made during verification.
