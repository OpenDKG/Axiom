# Axiom 0.30.0

**Released:** 15 November 2026

0.30.0 makes Axiom, the guard and the DKG CLI agree on one DKG home, and proves the node accepts
that home's token before an install reports the DKG endpoint as connected (#307).

Axiom's paths disagreed: the Hermes config named the bundled
`...\agent-blackbox\.dkg`, Axiom's optional installer used `modules\dkg-home`,
`UpgradeDataGuard` backed up only the bundled path, and Setup probed a hard-coded
`127.0.0.1:9200` even when `api.port` said `9320`. A node started from a second home rejects the
guard's token with 401, so findings never reach the local graph even though the dashboard looks
connected.

## Highlights

- **One resolver for every DKG home.** `DkgHomeResolver` moved to `Axiom.Contracts` so Setup, the
  desktop and the tests share it: candidate homes, `api.port` parsing, and token parsing that skips
  the comment line the node writes above the token.
- **Setup starts the configured home instead of creating a second one.** When the Hermes config
  already names a DKG CLI and home, Setup starts that node; it only initializes a standalone home
  when no configured CLI exists.
- **Upgrade backup covers every home.** `UpgradeDataGuard` now backs up and restores the bundled,
  standalone and managed homes instead of one hard-coded path.
- **Identity assertion.** New `DkgIdentityProbe` reads the resolved home's own port and token and
  calls `GET /api/agent/identity`. A 401 is reported as a home/token mismatch with a warning that
  findings cannot be written to the local graph, instead of showing a connected endpoint.

request and the 401 mismatch path.

## Upgrade notes

Install over 0.29.0. The upgrade guard backs up the DKG identity from every candidate home before
the vendor installer and restores anything that disappears.
