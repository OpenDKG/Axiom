# Axiom 1.3.0

**Released:** 18 November 2026

## Memory footprint, streaming preflight and cleaner Blackbox module updates

### Bounded caches in long-running process monitoring and alerts

- **`ProcessIdentityResolver` PID cache bound:** `_cache` now evicts entries older than `_cacheLifetime` (30 s) and enforces a 512-entry ceiling (`MaxCacheEntries`), falling back to oldest-quarter eviction during bursts of short-lived PIDs.
- **Shield pending notification state:** `ShellViewModel.NotifyNewPendingApps` clears `_notifiedPendingApps` whenever `pending.Count == 0`, preventing resolved application paths from staying pinned in memory and ensuring future prompts are not suppressed if an app returns later.

### Streaming `ruleset.json` novelty check during threat sharing

- `ThreatShareCli.FindKnownIdentifiersInRuleset` streams `ruleset.json` in pooled 64 K-char chunks with overlap carry-over using `ArrayPool<char>.Shared`, exiting as soon as all candidate indicators are matched and avoiding loading large ruleset files as a single Large Object Heap string.
- `ThreatSharePreflight.EvaluateKnownStatus` lets `AgentsPageViewModel` pass the streaming result without altering `ThreatSharePreflight.Evaluate(..., string? rulesetJson)` or `ThreatSharePreflight.IsAlreadyKnown`.

### Clean `agent-blackbox` working tree before vendor updates

- `OptionalModuleInstaller` (Avalonia `Presentation` and WPF `UI`) runs `git -C agent-blackbox checkout -- .` before invoking the pinned Blackbox installer when `agent-blackbox\.git` exists, preventing tracked CRLF or local file drift (such as `bip39_english.txt` normalization) from blocking vendor pulls.
