# Axiom 1.2.0

**Released:** 17 November 2026

## Blackbox and DKG can be repaired and come back after a restart

### Uninstall works on Windows PowerShell 5.1

The Blackbox and DKG uninstall scripts called
`String.Contains(string, StringComparison)`. That overload exists only in .NET Core; Windows
PowerShell 5.1 is .NET Framework and threw:

> Cannot find an overload for "Contains" and the argument count: "2".

Both scripts now use an ordinal `IndexOf` check. The cleanup also:

- stops the dashboard, its sync process, the DKG supervisor and worker in one pass;
- removes both Axiom's and the vendor login tasks (`Agent Blackbox dashboard`,
  `Agent Blackbox DKG node`, `Axiom …`);
- removes the Hermes plugin copy as well as the module tree;
- reports the remaining path instead of pretending success when a running process holds a file.

### Repair button

Agent Protection now has a **Repair** action for Blackbox and DKG. It stops a stale or duplicated
runtime, starts exactly one node/dashboard, and waits for the port before reporting. A missing
runtime still goes through the normal Install/Repair path so the vendor installer can rebuild it.

### Restart, crash and power-loss recovery

- Starting a module first checks its port. A node that is already binding is left alone, so the
  vendor login task and Axiom no longer race and leave duplicate processes.
- Axiom retries an installed-but-down module (at most five times, three minutes apart) instead of
  giving up for the session after the first attempt.
- The DKG card now also probes Blackbox's bundled node on **9320**, not only the historical 9200,
  so a healthy node is no longer reported as "not running" when the dashboard is down.

## Module controls are one clear layout

The single row of `Start / Uninstall / Audit / Block` is gone:

- **Start local modules** starts the DKG node first, then the Blackbox dashboard.
- Each service keeps its own **Start** or **Install** action, plus **Repair** when it is installed.
- **Audit** and **Block** are a labelled enforcement-mode selector inside the Blackbox card, with
  the active mode highlighted and one sentence explaining the consequence.
- The card footer explains what is lost when DKG is down: local blocking keeps working, but
  shared-graph evidence and publishing stop.

## Python prerequisites are validated before install

- Setup and Agent Protection accept only **Python 3.11-3.13**; 3.12 is installed when no compatible
  interpreter exists. A 3.15-only machine no longer counts as "Python present".
- The compatible interpreter is put first on the installer PATH; Axiom validates `python` directly
  and no longer creates a `py.cmd` shim that could fall back to an incompatible interpreter.
- A Complete install that still cannot satisfy the prerequisites skips the vendor installer with a
  clear message instead of running it into a Python traceback.
- The vendor is told not to reuse an existing Hermes installation, which removes the
  `hermes.exe --version` traceback path.

## Verification

- `dotnet build Axiom.sln -c Release` — 0 warnings, 0 errors.
- New tests: Python 3.15 rejection and compatibility selection, bootstrap on an incompatible
  interpreter, PowerShell-5.1-safe uninstall scripts, and the direct 9320 DKG probe.
- Existing Contracts, Core, Infrastructure, MCP, Persistence, Presentation, Service and UI suites
  pass.
- Installed on the host; the installer, Repair and the module cards were exercised locally.
