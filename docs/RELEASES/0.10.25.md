# Axiom 0.10.25

**Release date:** 2026-11-11

Axiom now uses the DKG node Blackbox already runs instead of installing and probing a second,
unused node.

## What was wrong

Complete installation installed Blackbox (which runs its own DKG node) and then installed a second
standalone DKG node for Axiom. Axiom's node was not used by threat sharing or the graph view, which
both go through Blackbox. The second node added another libp2p node, auto-updater and Oxigraph
store, and could collide with Blackbox's node on the default port. The DKG card also probed only
9200, so it could show a green module for whichever node happened to answer there.

## What changed

- `OptionalModuleProbe.ProbeDkgAsync` first probes the configured standalone endpoint. If nothing
  answers there, it reads `dkg_url` and `node_reachable` from Blackbox's `/api/graph-status`,
  accepts only a loopback URL with the documented `/api/status` shape, and reports the result as
  "DKG node reported by Blackbox".
- A malformed or non-DKG listener on 9200 still returns `UNKNOWN`; the fallback is used only when
  no node answers at the standalone endpoint.
- Complete installation asks Blackbox for its DKG node after the Blackbox installer. If the node is
  reachable, it skips the standalone DKG installer and logs that choice. If not, it installs the
  pinned standalone node as before.
- The Agents health line is labelled `DKG` rather than `Axiom DKG`, since the node may be
  Blackbox's.
- `docs/THREAT_INTELLIGENCE.md` describes the fallback and the skipped second node.

## Limits

- The fallback trusts Blackbox's `dkg_url` after requiring loopback and a valid DKG status. It does
  not verify a peer identity against an expected value yet.
- A machine that already has both nodes keeps them; this change affects new complete installations
  and the display. Removing an existing unused node is left to the user.
- When both nodes answer, the standalone 9200 node is still preferred and the Blackbox node remains
  visible in the graph health line.

## Verification

- `dotnet build Axiom.sln -c Release`: 0 warnings, 0 errors.
- `dotnet test Axiom.sln -c Release`: 565 passed, 0 failed. A new probe test covers 9200 refused,
  Blackbox graph status reporting 9320, and a valid status on 9320.
- Local machine check: Axiom's node answers on 9200 and Blackbox reports 9320, so the existing
  display stays as before; no node was stopped, started or installed during verification.
