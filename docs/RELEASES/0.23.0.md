# Axiom 0.23.0

**Released:** 14 November 2026

0.23.0 turns the complete installation into the protected default and hardens the agent bridge
end to end. A full install now writes block mode, installs the hooks, applies the Trader Shield and
the longer plugin load deadline, and proves itself with a self-test. The OpenCode bridge blocks the
whole action chain around protected data — read, write, copy, delete, launch and upload — and
quarantines a session on a high-severity prompt injection. Sharing is reputation-safe, and an
upgrade backs up findings, history and identity before the vendor installer runs.

This release also merges the `0.18.0`–`0.22.0` line: the threat-share pipeline, the E1/E2
enforcement receipts, the scoped firewall and trusted file broker work, the offline DKG annotator,
encrypted DoH, eight Privacy Shield sources and the offline continuity model.

## Highlights

- **A complete install is protected out of the box (`4ecb41f`, `2436929`, `8bd16e4`, `d7347d6`).**
  First start writes `mode: block`, runs `AgentProtectionSelfTest` (allowed read, protected read,
  protected write), provisions every agent hook, adds the Trader Shield for eleven wallets and sets
  `plugins.load_timeout_seconds: 120` so a slow disk does not drop the plugin.
- **The agent bridge covers the full action chain (`f860111`, `582d726`).**
  Beyond the vendor rules, it blocks protected-path deletes, guard tampering, remote script pipes
  (`curl | sh`, `iwr | iex`), encoded PowerShell, certutil/bitsadmin/mshta downloads, Run-key and
  scheduled-task persistence, launching a protected file (`Start-Process`, `&`, `cmd /c`,
  `rundll32`, `mshta`) and uploading one (`curl -F/-T/-d @`, `iwr -InFile`, `scp/sftp/ftp`,
  `certutil -encode`). A high-severity injection finding quarantines the session and blocks every
  later tool call for fifteen minutes.
- **Reputation-safe sharing (`4ecb41f`, `19f1a25`).** A local preflight refuses missing
  consent/key, values outside the closed vocabulary, known indicators, canaries, EICAR, advertising
  and tracking hosts, shared hosting, CDNs and disposable tunnels. The reporter runs through the
  committed Hermes interpreter first, then the vendor launcher, then the reporter module, so a
  packaging mismatch no longer looks like a dead button.
- **An upgrade cannot silently lose history (`16a68e2`, `74e5c50`, `d6b038f`).** `UpgradeDataGuard`
  copies `hermes\blackbox`, the Axiom history files and the DKG identity before the vendor installer
  and restores anything missing or empty; a grown file is never rewritten. The setup waits for a
  stopping service, retries a locked file and prints silent failures. The Trader Shield replacement
  no longer deletes keys after the shields block, so block mode and protected paths survive a
  restart.
- **Seed-phrase detection restored on Windows (`87efb9d`).** The installer normalizes
  `bip39_english.txt` to LF, matching the vendor's pinned SHA-256 (`2f5eed53…`, 13,116 B) and
  removing the "wordlist does not match" warning.
- **Offline continuity and honest enforcement labels (`0.22.0` line).** `BlackboxLocalState`
  distinguishes guard availability, cached rules, stale sync, DKG offline and unprotected; the UI
  no longer marks hooked agents offline when the dashboard port is down or the DKG is stopped.

## Verification

`dotnet test Axiom.sln` passed across all **9** test assemblies: **908/908** tests, 0 failed,
0 skipped.

In the lab Windows 11 VM: complete install `AXIOM_EXIT=0`; protected read/write blocked by the

NjRAT sample blocked; benign notepad and HTTPS calls allowed; prompt injection quarantined; upgrade

normalization.

## Upgrade notes

Install over 0.22.0 as usual. Local Blackbox state (`%LOCALAPPDATA%\hermes\blackbox`), the reporter
key, agent hooks and the DKG identity are backed up and preserved. Community sharing remains off by
default.

## Known limits

- File protection for an agent running as the signed-in user is enforced at the hook layer
  (`HOST_DENY_VERIFIED`); Axiom does not install a kernel driver or rewrite ACLs.
- Network blocking is an OS boundary (`OS_DENY_VERIFIED`) and is opt-in where Windows asks for
  consent.
- A cold DKG start can take several minutes while it catches up; the UI reports the state instead of
  calling the guard offline.
