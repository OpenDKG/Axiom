# Axiom 0.23.2

**Released:** 14 November 2026

Patch release for a protected-path delete gap found in the lab. Shell deletion of a file under a
wildcard protected directory (`~/.ssh/*`, `C:\Lab\samples\*`) was allowed because the delete check
derived an empty stem from the pattern; reads, writes and copies of the same file were blocked.

## Highlights

- **Wildcard protected directories are covered by shell deletes (`22766fa`).** `_deletes_protected`
  now uses the same path tokens as the launch and upload checks, so `~/.ssh/*` resolves to `.ssh`
  and `del C:\Users\lab\.ssh\id_rsa`, `rm -rf ~/.ssh` or `Remove-Item` on a protected path block.
- Includes **0.23.1** (silent module windows, complete setup provisioning) and **0.23.0**
  (complete-install protection, full action-chain guard, reputation-safe sharing, upgrade data
  guard, BIP-39 LF fix).

## Verification

`dotnet test Axiom.sln` — **926/926** tests across all 9 assemblies, 0 failed, 0 skipped.

In the Windows 11 lab VM, after an offline reboot (NAT off, DKG stopped) and with the patch applied:

| Action | Decision |
| --- | --- |
| `.env` write | block (`fileaccess:write:user-protected`) |
| `~/.ssh` read | block (`fileaccess:read:user-protected`) |
| `~/.ssh` shell delete | **block** (new) |
| `Start-Process` protected file | block (launch) |
| `curl -F file=@` protected file | block (exfiltration) |
| prompt injection | block + session quarantine |
| `Start-Process notepad.exe`, plain HTTPS call | allow |

## Upgrade notes

Install over 0.23.x as usual. The upgrade guard backs up `hermes\blackbox`, the Axiom history and
the DKG identity before the vendor installer and restores anything that disappears.
