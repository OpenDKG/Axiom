# Axiom 0.10.9

**Release date:** 2026-11-10

Privacy Shield blocklist updates are now pinned and verified.

## What changed

- **HaGeZi is pinned to a commit.** The catalogue pointed at `@latest`, so the upstream content
  could change without any local record. The URL now names commit
  `924bb2a8306e609ae8b0113c2b676f5fde072d16`, which makes the content reproducible.
- **Digest verification.** The catalogue stores the SHA-256 of that file
  (`ECF78F54E65FD78F70FB1636CE6BBAD563306246F8C00CDCDCE18B1C8BE01A7A`). The updater hashes the
  downloaded bytes before parsing; a mismatch throws, the source is reported as failed, and the
  previous ruleset is kept.
- **Single-label entries are rejected.** `NormalizeDomain` now requires at least one dot, so a bad
  or malicious line such as `com` cannot block an entire TLD. `ParseList` skips those lines like
  other invalid input.

## Limits

- Only HaGeZi carries a digest. OISD, WindowsSpyBlocker, the Block List Project and URLhaus are
  fetched over HTTPS with the same 20 MB cap but are still not signed; pinning them needs their own
  stable references and digests.
- Updating a pinned list is now a code change (new commit and digest), not an automatic `@latest`
  refresh.

## Verification

- `dotnet build Axiom.sln -c Release`: 0 warnings, 0 errors.
- `dotnet test Axiom.sln -c Release --no-build`: 493 passed, 0 failed.
- New tests: the catalogue URL contains the pinned commit and a 64-character digest; `com` and
  `localhost` are rejected while `example.com` is accepted.
