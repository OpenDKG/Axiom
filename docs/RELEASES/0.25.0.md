# Axiom 0.25.0

**Released:** 14 November 2026

0.25.0 fixes the post-install self-test on any account that is not the lab user. The protected-read
check read `C:\Users\lab\.ssh\id_rsa` on every machine; on a normal account that path does not match
the protected pattern, the read is allowed, and `protection-status.json` reports **UNPROTECTED**
even though block mode is active and the protected write blocks. The check now reads the signed-in
user's `.ssh\id_rsa`.

## Highlights

- **The self-test targets the current profile (`a57ebbe`).** `AgentProtectionSelfTest.DefaultChecks`
  builds the protected-read path from `Environment.SpecialFolder.UserProfile`; a test pins it to the
  current user so a hard-coded lab path cannot return.
- Includes **0.24.0** (default encrypted RFC 8484 DoH on port 443) and the 0.23.x line.

## Verification

`dotnet test Axiom.sln` — **926/926** tests across all 9 assemblies, 0 failed, 0 skipped.

Found on the host with 0.24.0: block mode true, protected write blocked, protected read **failed**
(`C:\Users\lab\.ssh\id_rsa` does not exist for `llm`), so `protection-status.json` said
`unprotected`. The VM with 0.24.0 passed because its user is `lab`. This release makes the check
portable.
