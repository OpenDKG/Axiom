# Axiom 0.10.22

**Release date:** 2026-11-11

The optional-module probes now require each module's documented identity instead of treating any
listener on the usual loopback port as connected.

## What was wrong

`OptionalModuleProbe` returned `CONNECTED` for:

- DKG: any 2xx from `http://127.0.0.1:9200/api/status`, even when the JSON was unreadable;
- Blackbox: any HTTP status from `http://127.0.0.1:9700/api/graph-status`, including 404 and 500.

A dev server, another tool or malware squatting the port could therefore produce a green module
card, and the Blackbox control centre would go on to read settings from it and send settings
changes and sync requests to that process.

## What changed

- DKG is `CONNECTED` only when `/api/status` returns an object with a non-empty `version`,
  `peerId` starting `12D3Koo`, `nodeRole` and a `networkId` from the known testnet/mainnet set.
  Missing fields, an unrecognised network id or a non-object response return `UNKNOWN` with the
  reason. The detail still shows version, peer, role and network name.
- Blackbox is `CONNECTED` only when `/api/graph-status` returns 2xx JSON with the dashboard fields
  `mode`, `node_reachable`, `dkg_url` and `sync_progress`. Any other response or a different JSON
  shape returns `UNKNOWN` with "not treated as the dashboard".
- HTTP errors are no longer connected; they report the status code and remain `UNKNOWN`.
- `docs/INTEGRATIONS.md` documents the accepted fields.

## Limits

- The known network ids are compiled in. A future DKG network needs an Axiom update; until then
  its node is reported as `UNKNOWN` with its id, not silently accepted.
- The probes still have no signed proof that the process owning the listening socket is the
  expected binary. Socket→process attribution and executable checks are a separate improvement.

## Verification

- `dotnet build Axiom.sln -c Release`: 0 warnings, 0 errors.
- `dotnet test Axiom.sln -c Release`: 559 passed, 0 failed. New cases cover a non-DKG JSON listener,
  missing fields, a non-libp2p peer id, an unknown network id, a non-Blackbox 2xx response and a
  404 from the Blackbox port.
- Live endpoints were checked before the change: DKG `/api/status` returns the documented fields
  with the testnet network id, and Blackbox `/api/graph-status` returns the four expected fields,
  so both should remain `CONNECTED` after install.
