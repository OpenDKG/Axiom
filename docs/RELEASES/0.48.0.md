# Axiom 0.48.0

**Released:** 15 November 2026

0.48.0 comes from the first **live Gemini CLI sweep**: Gemini CLI 0.68.0 was installed in the lab
VM after Codex and Claude, Axiom provisioned `~/.gemini/settings.json`, and the same vector families
were run through the Gemini hook.

## What the live sweep found

| Hook under test | Result |
| --- | --- |
| Installed 0.30.0 Gemini hook | **2/15** (only the two controls) |
| Generated 0.47.0 hook | 2/15 |
| Generated 0.48.0 hook | **15/15** |

Three defects in the shared hook template, all specific to Gemini:

1. **Event name.** Gemini fires `BeforeTool`; the hook matched only `pretooluse`/`pre_tool_use`, so
   the entire pre-tool path never ran. `beforetool` / `before_tool` are now accepted.
2. **Deny shape.** Gemini expects `{"decision":"deny","reason":…}`; the hook returned the Claude
   `hookSpecificOutput` shape. Gemini now gets its own shape.
3. **File argument.** Gemini's `read_file` passes **`absolute_path`**. The guard now maps it to
   `path` for the vendor file-access rules and includes it in `_arg_path` for the Axiom store check.

## Verification

- Gemini live vectors with the 0.48.0 generated hook: **15/15** (controls allow; `$HOME`, `\\?\`,
  move, takeown, upload, `reg save SAM`, procdump lsass, `sc create`, Register-ScheduledTask,
  `.git-credentials`, wallet keystore and injection all block).
- New template test asserts the event names, the Gemini deny shape and the `absolute_path` mapping.
- `dotnet build Axiom.sln -c Release` — 0 warnings, 0 errors.
- `dotnet test Axiom.sln -c Release --no-build -m:1` — full suite in the release run.

## Upgrade notes

Install over 0.47.0, then restart the desktop once so it reprovisions `~/.gemini/settings.json` and
the shared hook script. Installed-build verification is still pending the owner's upgrade.
