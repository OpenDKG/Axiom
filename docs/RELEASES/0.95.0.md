# Axiom 0.95.0

**Released:** 17 November 2026

## The publish-only NU1009 warning is gone

Nine projects still carried an explicit `Microsoft.NET.ILLink.Tasks` package reference from the
.NET 9 era, and Central Package Management pinned it. The .NET 10 SDK adds that package itself
when `PublishTrimmed` is used, so restore rejected the duplicate and publish warned:

```
NU1009: The following PackageReference items are implicitly defined and cannot define a PackageVersion item: Microsoft.NET.ILLink.Tasks
```

- Removed the explicit reference from `Axiom.Contracts`, `Core`, `Desktop`, `Desktop.Avalonia.Windows`,
  `Infrastructure.Windows`, `Persistence`, `Presentation`, `Service` and `UI`.
- Removed the `Microsoft.NET.ILLink.Tasks` pin from `Directory.Packages.props` and refreshed the
  committed `packages.lock.json` files.
- Trimming still runs; the SDK supplies the same task package during publish.

## Pentesting evidence updated

The pinned DKG node came up on the 0.93/0.94 installs and stayed stable (port 9320, API 200, 8/8
stability probes) after the documented launcher workaround, so `docs/PENTESTING.md` no longer says
the node is permanently offline. The verified-graph sync is recorded in the evidence table; when
the node does not start, the compiled ruleset still enforces and the dashboard reports it offline.

## Verification

- `dotnet build Axiom.sln -c Release` — 0 warnings, 0 errors.
- `dotnet publish src/Axiom.Setup` with trimming — no NU1009/ILLink package warning.
- Windows CI (build, tests, packaging check) passes; 0.95.0 installed in the VM.
