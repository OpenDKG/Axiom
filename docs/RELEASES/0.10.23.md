# Axiom 0.10.23

**Release date:** 2026-11-11

Every part of Axiom that touches the Hermes/Blackbox profile now resolves the same path, and the
Threat sharing card shows which profile the reporter uses.

## What was wrong

Different components disagreed about the Blackbox home:

- `ThreatShareCli` forced `HERMES_HOME=%LOCALAPPDATA%\hermes` and checked consent only there;
- `BlackboxModeStore` wrote `~\.hermes\config.yaml`;
- the uninstaller removed `~\.hermes\blackbox`;
- `BlackboxLocalState` checked both locations in a fixed order;
- the official installer also honours `HERMES_HOME`/`BLACKBOX_HOME`.

On a Windows install the active profile is `%LOCALAPPDATA%\hermes`, so the mode store and
uninstaller pointed at a stale legacy folder while the reporter used the live one. A mode written
to the wrong config would not apply, and an uninstall would leave the reporter key, consent and
audit files behind.

## What changed

- New `BlackboxPaths` resolves the profile once:
  `HERMES_HOME` when set, then `%LOCALAPPDATA%\hermes` when it looks like a profile, then the
  legacy `~\.hermes`, and `%LOCALAPPDATA%\hermes` as the final default. `BLACKBOX_HOME` overrides
  the blackbox folder inside it.
- `ThreatShareCli` uses the resolved home for `HERMES_HOME` and for `ConsentPath`; a new
  `DescribeReporterProfile` reports the path and whether `sharing_consent.json` and
  `reporter_key.pem` are present.
- The Agents threat-sharing card shows that reporter profile line. It is informational; nothing is
  sent by rendering it.
- `BlackboxModeStore` edits the resolved profile's `config.yaml` and keeps its line-preserving
  YAML edit and backup behaviour.
- `BlackboxLocalState` and `OptionalModuleUninstaller` use the same resolver; uninstall removes the
  active Blackbox home, not a hard-coded legacy path.
- `docs/INTEGRATIONS.md` documents the order and the override variables.

## Limits

- A profile that exists in both locations is resolved to `%LOCALAPPDATA%\hermes`; the legacy
  folder is left untouched rather than merged.
- The reporter still relies on the `hermes` CLI's own profile selection. If the CLI ignores
  `HERMES_HOME` in a future version, the card would show a path that the CLI does not use; the
  displayed consent/key state would then be the first visible sign.
- The mode buttons on the Security page are unchanged in behaviour; only the path they edit is
  corrected.

## Verification

- `dotnet build Axiom.sln -c Release`: 0 warnings, 0 errors.
- `dotnet test Axiom.sln -c Release`: 564 passed, 0 failed. New tests cover local-vs-legacy
  preference, the final default, environment overrides and the consent/key paths.
- Local profile check: `%LOCALAPPDATA%\hermes\blackbox` contains `sharing_consent.json` and
  `reporter_key.pem`; the legacy `~\.hermes` has only a config file and no blackbox folder.
  The new card should therefore show `%LOCALAPPDATA%\hermes` with consent and key present.
- No report was submitted during verification.
