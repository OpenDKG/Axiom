# Axiom 0.54.0

**Released:** 15 November 2026

0.54.0 resolves five issues observed on a clean Windows 11 laptop install: missing module prerequisites and broken Repair/Uninstall flows for Blackbox & DKG, false loopback status-check timeouts, adapter DNS failing to switch/stay on `127.0.0.1`, blocklist download failures dropping every feed, and high idle memory consumption in `Axiom.Service.exe` and `Axiom.Desktop.exe`.

## What changed

- **Module prerequisites, runtime detection, loopback probes, and uninstall scripts (`8ebe9e3`):**
  - Promoted `ModulePrerequisites` to `Axiom.Contracts.Modules`, adding `Microsoft.VCRedist.2015+.x64` support, `ModuleTool.Npm` -> `OpenJS.NodeJS.LTS` mapping, `Python 3.13` / `ProgramFiles(x86)` search paths, tolerance for winget exit code `-1978335189` (already installed), and non-interactive exit handling used automatically by `Axiom.Setup` `CompleteInstallation`.
  - Split `HasBlackboxFiles` / `HasDkgFiles` from `IsBlackboxRuntimeInstalled` (`venv\Scripts\python.exe` / `pythonw.exe`) and `IsDkgRuntimeInstalled` (`node_modules\.bin\dkg.cmd`) across `OptionalModuleUninstaller`, Avalonia `SecurityPageViewModel`, and WPF `SecurityViewModel`, offering `Repair` instead of dead-ending on `Start`.
  - Added `OptionalModuleProbe.CreateLoopbackHttpClient` (`SocketsHttpHandler { UseProxy = false, ConnectTimeout = 1s }`) for both probe checks and desktop Blackbox status polling so Windows WPAD auto-detection cannot stall loopback checks into false timeouts.
  - Consolidated `ModuleUninstallScripts` (`BuildBlackboxScript`, `BuildDkgScript`) eliminating the PowerShell `$HOME` read-only assignment bug (`$dkgHome`), waiting on terminated processes (`Wait-Process -Timeout 5`), clearing `ReadOnly` file attributes (e.g. `.git`), skipping reparse points, and guarding scheduled-task removal.
- **Privacy Shield DNS `127.0.0.1` auto-pointing & feed resilience (`5dde35f`):**
  - Configured `PrivacyShieldSourceUpdater` with `SocketsHttpHandler { UseProxy = false }` + IPv4-first `ConnectCallback` fallback, 3-minute download timeout, up to 3 bounded retries for transient resets/timeouts, and partial-source commit (activating rules from all reachable feeds with a clear warning if one host refuses connection, while still failing closed when zero feeds succeed).
  - Added `PrivacyDnsFailSafe.LastError`, stdout/stderr capture, and `netsh interface ipv4 set dnsservers` fallback when `Set-DnsClientServerAddress` fails, plus a 3-second post-start retry in `PrivacyShieldWorker` and bound `AutoPointAdapterDns` checkboxes across both Avalonia (`PrivacyShieldView.axaml`) and WPF (`PrivacyShieldView.xaml`).
- **Memory footprint reduction (`9a520b3`):**
  - Removed permanent retention of `_rules`, `_policyRules`, and raw-rule `_rulesTask` in `PrivacyShieldController`, packed catalog entries in `PrivacyShieldPolicy` via `PackedRule` (`Category` + interned `SourceId` palette index) and `WithSettings(...)` catalog sharing, replaced `text.Split` in `ParseList` with `TextReader` streaming, and used `GetAlternateLookup<ReadOnlySpan<char>>()` in `Evaluate`.
  - Streamed `PrivacyShieldRuleStore.Save()` directly to `FileStream` (removing giant LOH string/buffer spikes), pooled repeated `SourceId` strings on `Load()`, streamed feed parsing via `StreamReader` inside `PrivacyShieldSourceUpdater`, enabled workstation GC + `System.GC.ConserveMemory = 7` on `Axiom.Service` and `Axiom.Desktop.Avalonia.Windows`, and ran LOH compaction after rule loads and source updates.
