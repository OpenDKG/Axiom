# Axiom 0.3.0

**Release date:** 2026-11-11 (development PR; not published)

This development version adds a user-triggered read-only graph lookup and closes a provenance
failure mode in the AI Analyst queue. It is intentionally numbered `0.3.0` after the `0.2.0`
reset; see version compatibility below.

## Changes

### AI Analyst provenance fails closed

The analyst reads Axiom's local malware-list block history to suppress list-derived values. If that
lookup is unavailable (service down, timeout, unreadable response, or no service client), the
previous code used an empty set and could treat a list-derived value as independent.

- `ListDerivedValuesAsync` now returns availability with the set.
- When provenance is unavailable, no AI indicator is queued and the page status says why.
- `ThreatShareIocExtractor.Extract` also fails closed when `provenanceAvailable` is false.
- Regression tests cover the unavailable-provenance path.

### User-triggered Check graph

Blocked-domain rows in Privacy Shield have a **Graph** action.

- It calls the local Blackbox dashboard `/api/threat` for the `public`, `local` and `community`
  tiers, one identifier at a time.
- It is user-triggered only; there is no work on the per-connection or two-second refresh path.
- Each request is bounded to five seconds. Results are cached for ten minutes with a 256-entry cap;
  failures are not cached.
- The dialog reports the tier, category, sources and reporter count when the dashboard returns
  genuine per-indicator evidence.
- Not found, timeout, HTTP error or an entry without source/reporter provenance is shown as
  **Unknown, not clean**.
- Axiom does **not** display VERIFIED or COMMUNITY badges from this result. Automatic DKG
  annotations remain deferred.
- Only loopback endpoints are accepted; no DKG or external endpoint is contacted.

### Installer upgrade while the service runs

- Setup previously refused to start if any `Axiom.Service` process existed, including the registered
  Windows service. That made a normal 0.2.0 -> 0.3.0 Setup upgrade impossible without stopping
  protection first.
- Setup now blocks only running desktop processes. It stops an interactive service copy that lives
  in the selected install directory before copying, and leaves the registered Windows service for
  the elevated `--install-service` step. The elevated installer stops and replaces the service as
  before.

### Upstream request

`docs/THREAT_INTELLIGENCE.md` records the request to Umanitek for a documented per-indicator or
batch read-only lookup returning tier, sources, reporters and provenance (UAL/timestamp), plus a
truthful blocked/attempted-lookup context. This release does not contact Umanitek automatically.

## Version numbering and upgrade compatibility

- The project previously used `0.10.x`. The sequence was intentionally reset to `0.2.0`; `0.3.0`
  is the next increment.
- The portable ZIP and Setup copy files and do not compare version numbers. `0.3.0` upgrades an
  installed `0.2.0` normally. Upgrading a `0.10.x` install with `0.3.0` would be a numeric
  downgrade, so use this build only from `0.2.0` or as a fresh install.
- Store/MSIX packaging uses package versions and must not be republished with a lower version; the
  reset applies to the portable/Setup channel only.

## Verification

- `dotnet build Axiom.sln -c Release`: 0 warnings, 0 errors.
- `dotnet test Axiom.sln -c Release`: 574 passed, 0 failed.
- Desktop/service/installer builds are produced by `scripts/build-release.ps1` and
  `scripts/publish-setup.ps1`; all three report version `0.3.0`.
- Installer upgrade smoke test, with the Windows service still running: a temporary directory was
  seeded with the installed 0.2.0 desktop/service, then
  `Axiom.Setup.exe --silent --partial --accept-risk --no-launch --no-shortcut --install-dir <temp>`
  exited `0` and both files reported `0.3.0`. The active install and protection settings were not
  changed; the partial profile marker was restored afterward.
- Live Check graph: the first blocked row (`ioc:domain:v20.events.data.microsoft.com`) returned
  "No entry found in the public, local or community graph. Unknown, not clean" with reporters 0.
  No VERIFIED/COMMUNITY badge was shown.
- Another listener/unknown case is covered by unit tests: HTTP error, malformed result, missing
  provenance, non-loopback endpoint and cache expiry all return the expected result.

## Remaining limitations

- Blackbox's `/api/threat` returns no per-IOC entries for ordinary domains on this host; Check graph
  therefore usually reports Unknown/not found. That is intentional and not a clean verdict.
- Automatic annotations and badges wait for the upstream per-indicator/batch lookup.
- `in-tool-output` remains the closest available context for AI Analyst reports until Umanitek adds
  a truthful observed-endpoint context.
