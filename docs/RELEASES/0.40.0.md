# Axiom 0.40.0

**Released:** 15 November 2026

0.40.0 adds the de-duplication layer between the future process-creation subscription and the F-19
policy: the service will observe many duplicate process events, and only distinct, non-allowed
children should reach the graph.

## What this adds

- `AgentProcessSpawnMonitor` (`src/Axiom.Core/Enforcement`):
  - calls `AgentProcessSpawnPolicy.Evaluate` and drops `Allow` verdicts;
  - returns one audit row per distinct `(image, pid, parent)` observation, so a polling ETW/WMI
    feed cannot flood the graph;
  - remembers at most N observations (default 256), evicting the oldest;
  - pure, no I/O; the subscription and any termination stay in `Axiom.Service`.
- `ProcessSpawnAudit` pairs the raw event with the `Record`/`Block` decision.

## Verification

- 6 new tests: allowed child dropped, staged exe recorded as Block, duplicate suppressed,
  allowlist honored, capacity eviction, distinct pid treated separately.
- `dotnet build Axiom.sln -c Release` — 0 warnings, 0 errors.
- `dotnet test Axiom.sln -c Release --no-build -m:1` — full suite in the release run.
- **Live VM verification is pending install**; the ETW/WMI subscription is the next step.

## Upgrade notes

Install over 0.39.0. No runtime behaviour change yet; the monitor is not wired to the service.
