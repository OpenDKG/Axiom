# Axiom 0.35.0

**Released:** 15 November 2026

0.35.0 adds Axiom-owned detection for credential stores the vendor protected-path list does not
name, and for credential enumeration commands. Found by the attack-vector sweep on 0.30.0
(`.git-credentials`, `.npmrc`, `.kube/config`, GitHub CLI, browser login/cookie databases, Firefox
profiles and wallet files were readable).

## Fixes

- **Sensitive credential stores.** `_sensitive_store` normalizes the path (shell variables and
  Win32 prefixes included) and blocks access to:
  - `.git-credentials`, `.npmrc`, `.kube\config`, `.docker\config.json`
  - GitHub CLI `hosts.yml`
  - browser `Login Data`, `Network\Cookies`, `Local Extension Settings`
  - Firefox `profiles`, `wallet.dat`
- **Credential enumeration commands** in the shared `_escalation_risk`:
  `cmdkey /list`, `vaultcmd`, `netsh wlan … key=clear`, certificate export
  (`Export-Certificate`, `certutil -exportpfx`).
- The OpenCode bridge checks the command text and the translated `path`/`filePath` argument, so a
  `read_file` of a browser credential database is blocked even when no shell command is involved.
  The shared `_check_command_safety` applies the same check to the other host adapters.

## Verification

- `dotnet build Axiom.sln --nologo` — 0 warnings, 0 errors.
- `dotnet test Axiom.sln -c Release --no-build -m:1` — full suite (recorded in the release run).
- Template tests assert the detector, the store markers and the enumeration labels run before the

- **Live VM verification is pending install.** The lab VM stays on 0.30.0 until the owner installs;
