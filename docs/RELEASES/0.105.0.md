# Axiom 0.105.0

**Released:** 17 November 2026

## New agent blocks raise one alert, not a storm (FND-007)

The Agent Dashboard and Activity pages show blocked tool calls, but nothing interrupted the user
when a new block happened. A busy guard can block dozens of calls a minute, so a toast per block
would be unusable.

- New blocks that arrive through the activity poll now raise **one** notification, at most once per
  five minutes, with the number of blocks since the last alert and a sample (`codex read
  ~/.ssh/id_rsa`).
- History loaded at startup is treated as a baseline and never alerts.
- The alert is recorded in the in-app notification history even when tray notifications are off,
  and its Open action goes to **Agent Activity**.
- The policy is a pure class (`AgentBlockAlertPolicy`) with tests for the baseline, the sample
  message, cooldown batching (3 + 2 + 1 becomes 6) and zero/negative counts.

## Verification

- `dotnet build Axiom.sln -c Release` — 0 warnings, 0 errors.
- `AgentBlockAlertPolicyTests` pass; the UI wiring builds.
- Windows CI build, tests and packaging check pass; 0.105.0 installed on host and in the VM.

## Scope

This is the alert half of FND-007. WFP/5157 blocked-event evidence is still open: OS-level deny is
not enabled by default, so Axiom cannot read 5157 events for actions it did not block.
