# Axiom 0.91.0

**Released:** 17 November 2026

## Row context menus open on the row you clicked (issue #296)

0.90 disabled the ScrollViewer's built-in scroll menu, but the row menu still never appeared on the
installed build: right-clicking selected the row (the details pane filled in) and no popup opened.
The menu was attached to the row template inside the `ListBox`. A `ListBoxItem` takes the
right-click for selection and keeps the pointer, so Avalonia raises `ContextRequested` on the item
container, never on the template root below it. The menu attached inside the template was therefore
unreachable — before 0.90 the search simply continued up to the ScrollViewer and opened its scroll
menu instead.

- The activity and findings menus now live on the `ListBox` itself, which is an ancestor of the
  item, so the menu opens for every right-click. 0.90's `ScrollViewer.ContextMenu = null` style
  stays, so the scroll menu cannot win the lookup first.
- Menu items copy the ListBox's `SelectedItem`, and `DataListSelection` still selects the row on
  pointer press, so the menu always acts on the row under the pointer.
- Applied to the Agent Dashboard (activity, findings) and Agent Activity page (activity, findings,
  hook evidence).

## Verification

- `dotnet build Axiom.sln -c Release` — 0 warnings, 0 errors.
- New UI test: right-clicking a row opens the list menu, its item is bound to that row, and running
  the item copies that row.
- Installed in the VM; right-click on a row shows Copy event / Copy details / Copy raw event JSON.
