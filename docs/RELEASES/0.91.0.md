# Axiom 0.91.0

**Released:** 17 November 2026

## Row context menus live on the list, not inside the row template (issue #296)

0.90 disabled the ScrollViewer's built-in scroll menu, which had been swallowing the row menu, and
VM verification confirmed that the row menu (Copy event / Copy details / Copy raw event JSON) then
opened and selected the row under the pointer.

The menus were still attached to the root `Grid` of each item template. That makes them depend on
where Avalonia raises `ContextRequested`: if a `ListBoxItem` keeps the right-click for selection,
the search starts at the item container and never reaches the template root below it. 0.91 moves
the menus onto the `ListBox` itself, an ancestor of every item, so the lookup succeeds in either
case.

- The activity and findings menus now sit on the `ListBox` and copy its `SelectedItem`;
  `DataListSelection` still selects the row on pointer press, so the menu acts on the row under
  the pointer.
- Applied to the Agent Dashboard (activity, findings) and Agent Activity page (activity, findings,
  hook evidence).
- 0.90's `ScrollViewer.ContextMenu = null` style stays, so the scroll menu cannot win the lookup.

## Verification

- `dotnet build Axiom.sln -c Release` — 0 warnings, 0 errors.
- New UI test: right-clicking a row opens the list menu, its item is bound to that row, and running
  the item copies that row.
- VM, installed 0.91.0, UI Automation: right-click a row → `context_menu=OPEN` with
  `Copy event / Copy details / Copy raw event JSON`, the row is selected, and `Copy event` fills
  the clipboard.
