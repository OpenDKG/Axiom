# Axiom 0.50.0

**Released:** 15 November 2026

0.50.0 makes a Complete install reuse an already-installed Blackbox instead of re-running the
vendor installer every time, and recovers automatically when the pinned vendor build fails its own
Hermes dependency check.

## Fixes

- **Reuse the pinned Blackbox build.** After a successful vendor install Axiom writes
  `%LOCALAPPDATA%\Axiom\modules\blackbox\.axiom-blackbox-build` with the pinned installer digest.
  A later Complete install with the same digest and a working vendor venv logs "already installed;
  reusing the existing runtime" and skips the vendor download/install entirely. A new pinned digest
  still forces a reinstall.
- **Automatic Hermes repair.** The pinned vendor installer can exit 1 with
  `hermes: no dependency environment is committed for this install; run 'hermes pm repair'`
  (seen on 0.49.0). Axiom now runs `hermes pm repair` once after a non-zero vendor exit, then treats
  the install as successful when the vendor venv exists; a missing venv still fails loudly.
- Node and DKG were already reused: the installer probes the existing Node/npm toolchain, skips
  Axiom's standalone DKG when Blackbox provides one, and starts the configured DKG home instead of
  creating a second one.

## Verification

- The 0.49.0 upgrade log showed the backup drop from **8,307 MB / 116,903 files** to **58.3 MB /
  184 files** and reached the vendor step in 26 seconds.
- `hermes pm repair` was run manually on the host and repaired the runtime
  (`Hermes Agent vgit.a6db1f7...` then answers); the script now does this automatically.
- `dotnet build Axiom.sln -c Release` — 0 warnings, 0 errors.
- `dotnet test Axiom.sln -c Release --no-build -m:1` — full suite in the release run, including the
  new marker-reuse test.

## Upgrade notes

Install over 0.49.0. The first Complete install after this release still runs the vendor installer
once to create the marker (or reuses the repaired runtime); subsequent upgrades skip it.
