# Axiom 0.10.14

**Release date:** 2026-11-10

The Antigravity entry in **Protected workspaces** now displays and detects correctly.

## What was wrong

The 0.10.13 row existed but used the internal key as its label (`antigravity`, lowercase), and the
process probe had no Antigravity case. A running Antigravity therefore still produced the text
“start Antigravity to verify runtime loading”, which made the row easy to miss and misleading.

## What changed

- `ProtectedAgent.KindText` maps `antigravity` to **Antigravity**.
- `AgentProcessProbe` recognises the running `Antigravity` process (Windows process name is
  capitalised) as well as `antigravity`.
- While Antigravity is running with the hook installed, the detail now says the hook is installed but
  no invocation has been observed yet, and to restart Antigravity if it started before the hook.

## Verification

- `dotnet build Axiom.sln -c Release`: 0 warnings, 0 errors.
- `dotnet test Axiom.sln -c Release`: 500 passed, 0 failed.
- Live: the Protected workspaces list now shows `Antigravity`, target
  `C:\Users\llm\.gemini\config\hooks.json`, and a running-process hint while Antigravity (8 processes)
  is up.
