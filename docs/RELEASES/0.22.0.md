# Axiom 0.22.0

**Released:** 14 November 2026

0.22.0 guarantees honest offline runtime continuity for Agent Blackbox protection after initial DKG synchronization, separating guard availability, local cached rulesets, sync staleness, DKG node reachability, and missing/corrupted cache states instead of conflating dashboard port `9700` or DKG connectivity with unprotected agent hooks (#324).

## Highlights

- **5-state offline continuity model & cache preservation (`6838979`).**
  - Added `BlackboxContinuityReport` and `BlackboxLocalState.EvaluateContinuity(...)` in both `Axiom.Presentation` and `Axiom.UI.Services` tracking `GUARD_AVAILABLE`, `RULESET_AVAILABLE`, `SYNC_STALE`, `DKG_OFFLINE`, and `UNPROTECTED` plus cache corruption, stale curator manifests, and refused kill-lists.
  - Removed the false 10-minute `authoritative-sync.json` expiry cliff in `TryReadSync`: valid cached `ruleset.json` rules survive beyond 10 minutes and offline reboots (recovering timestamps for `DkgContextAnnotator.IsStaleCache`), while corrupted or missing `ruleset.json` returns `unavailable` (`VerifiedRules = 0`) even if `authoritative-sync.json` looks recent.
  - Updated `TryReadGraph` to aggregate `verified_scope.verified_counts` (`dependency` and `ioc` counts) offline when `authoritative-sync.json` is absent.
- **Dashboard port `9700` decoupled from agent protection classification (`5c72c17`).**
  - Updated `SecurityPageViewModel` (Avalonia) and `SecurityViewModel` (WPF) so `RefreshAgentsAsync` evaluates `BlackboxLocalState.EvaluateContinuity()` when the dashboard UI port (`9700`) is closed, preventing hooked agents from showing `OFFLINE` while the local guard and `ruleset.json` remain active.
- **Offline Continuity Audit & Upstream RFC (`ceaa01c`, [OFFLINE_CONTINUITY_AUDIT.md](../OFFLINE_CONTINUITY_AUDIT.md)).**
  - Documented zero-graph vs compiled `ruleset.json` vs `DKG-lookup B6` Oxigraph store dependencies, isolated offline circuit-breaker timings (`2,171.7 ms` first timeout -> `7.7–8.5 ms` subsequent calls), and two upstream Blackbox RFC items (`verified_lookup_fallback: "index"` default + Windows CRLF fix for pinned `bip39_english.txt`).

## Verification
