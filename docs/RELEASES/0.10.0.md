# Axiom 0.10.0

**Release date:** 2026-11-09

Axiom 0.10.0 lets the indicators it actually observes reach the Blackbox community graph, under the
user's existing threat-sharing switch and Blackbox's own reporter. It deliberately shares far less
than "everything": only malware indicators an agent fetched and high-confidence AI Analyst IOCs.

## Sharing indicators with the Blackbox graph

- **Preview before anything leaves.** The Agents page shows the indicators Axiom observed, each with
  its type, source and the evidence that qualifies it. A candidate can be dismissed at any time.
- **Two honest sources only:**
  - a Privacy Shield block of a **malware-list domain that an agent process fetched** (the DNS query
    is attributed to its owning process, and only agent executables and paths qualify), shared with
    the `fetched-by-tool` context;
  - a high-confidence **AI Analyst** finding (`SUSPICIOUS`/`SUPPORTED_ALERT`, severity high or
    critical) that names a well-formed domain, URL, public IPv4 address or SHA-256 digest, shared with
    the `in-tool-output` context. Vendor domains, private addresses, file names and paths are skipped.
- **Ads, tracking, telemetry and spam are never proposed.** Blackbox's report schema has no ad or spam
  category. Sending them would be rejected or pollute the shared graph, so Axiom does not queue them.
- **The service never submits.** It attributes the query, keeps the durable queue and records the
  result. The desktop runs `blackbox report --type ioc ...` in the signed-in user's session, because
  the reporter key, the DKG identity and the reporter-terms consent live there, not in the service
  account. Blackbox applies its own consent, cooldown, daily cap (100) and high severity floor.
- **Off means off.** While threat sharing is off nothing is submitted; a forced attempt returns the
  CLI's own refusal ("Community sharing is OFF"). When sharing is on, queued indicators are submitted
  at most once a minute and each outcome (`shared`, `already shared`, `rejected: ...`) stays visible.

## Privacy Shield source change

- A dedicated malware-only source replaces the ambiguous malware tag: **URLhaus malicious domains**
  compiled by `malware-filter` (MIT, updated every 12 hours). OISD Big is now labelled as an
  ads/tracking list, and its malware coverage is covered by the URLhaus source.
- When two sources list the same domain, the categories are merged instead of the second source being
  skipped. A malware source therefore upgrades a domain already listed as an ad, so a shared
  indicator is never actually an ad. Source attribution stays with the first list that named it.
- A malware list larger than the 20 MB import limit is rejected with a clear error; the URLhaus domain
  feed is a few hundred KB.

## Verification

- `dotnet build Axiom.sln`: 0 warnings, 0 errors.
- `dotnet test Axiom.sln`: 466 passed, 0 failed. New tests cover indicator normalization and the
  closed vocabulary (domains, URLs, public IPs, hashes; ad/tracking and file-like values rejected),
  agent-process matching, the DNS-block decision (malware + agent only), queue deduplication across a
  restart, the category merge, and the AI-Analyst IOC extraction (noise and low-severity findings
  produce nothing).
- Installed the new service and desktop and verified end to end:
  - the six-source catalog compiled 490,603 rules including the URLhaus feed, whose overlapping
    domains upgraded 598 existing rules to the malware category;
  - a fetch of a malware-category domain from an `opencode`-path process produced a pending
    `Privacy Shield` candidate automatically, and nothing was submitted while sharing was off;
  - `threatshare.status/enqueue/record/dismiss` round-tripped over the pipe, including the rejection
    message from the Blackbox CLI when sharing is off.

## Known limitations

- The queue is a review list, not a curated feed: an AI Analyst candidate is a heuristic extraction
  from the finding text and should be dismissed if it is wrong.
- A DNS block is never shared on its own; the indicator must have been fetched by a recognised agent
  process and come from the malware list.
- Blackbox must be installed and reachable for submission; the preview still works without it.
- ETW telemetry is not integrated yet, and per-application traffic remains TCP-only.
