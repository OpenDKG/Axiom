# Axiom 0.2.0

**Release date:** 2026-11-11

Public-list matches stay local, local block provenance is recorded, and the AI Analyst can no
longer turn a public-list detection into a second, supposedly independent sighting.

## What was wrong

Privacy Shield proposed a malware-list domain to Blackbox whenever an agent tool triggered the
block. The domain was already on a public URLhaus feed, so every Axiom install reported the same
indicator and the community graph saw many "independent" sightings of one list. The report schema
has no field for the source list, so Axiom could not mark it as list-derived. Blocked history also
did not record which local rule or source produced a block.

## What changed

- `PrivacyShieldController` no longer has a threat-share entry point. `ObserveBlocked` and
  `CreateFromBlocked` are removed, so a blocked DNS lookup cannot become a community report.
- Blocked events now carry local provenance: matched rule, source id, source name, source version
  (pinned SHA-256 or last-update timestamp), Axiom version, `dns-blocklist-match` reason,
  `isListDerived`, `lookupBlocked` and the existing timestamp. The blocked-history tooltip shows it.
  It is never uploaded.
- `PrivacyShieldPolicy` carries the matching source id on each block decision, so provenance is
  exact rather than guessed from the category.
- The AI Analyst loads the local malware-list block history before proposing indicators. A domain
  or URL host already in that history is suppressed as list-derived; genuinely independent,
  evidence-bound indicators remain eligible.
- The Agents page and URLhaus source description stop claiming that list matches are shared.
- `docs/THREAT_INTELLIGENCE.md` records a proposed upstream schema: optional detection method,
  source id/version, blocked-versus-fetched and Axiom version, plus a truthful blocked-lookup
  context. Axiom does not invent unsupported Blackbox values.

## Compatibility

No Blackbox protocol change is made. The existing report fields are unchanged; only Axiom's local
queue and blocked history carry the new provenance fields. Existing `threat-share.json` and
`privacy-shield-blocked.jsonl` entries deserialize with empty provenance.

## Limits

- Axiom still cannot tell the graph that an AI Analyst report is independent of a public list
  beyond suppressing exact local matches. That needs the upstream schema.
- The local blocked history is capped at 1,000 entries, so a very old list match may have fallen
  out when the analyst runs. In that case the value is not suppressed by history.
- List matches remain visible in Privacy Shield and its counters; only community publication is
  removed.

## Verification

- `dotnet build Axiom.sln -c Release`: 0 warnings, 0 errors.
- `dotnet test Axiom.sln -c Release`: 565 passed, 0 failed. New tests cover source-carrying policy
  decisions, the absence of a `PrivacyShieldBlockedEvent` threat-share entry point, and AI Analyst
  suppression of a local list-derived domain while an observed IP remains eligible.
- Live service queue was not modified during verification; no report was submitted.
