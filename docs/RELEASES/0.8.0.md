# Axiom 0.8.0

**Release date:** 2026-11-08

Axiom 0.8.0 is the first release positioned as **Free Open-Source Network & AI Agent Security**. It
brings the Avalonia Windows UI to production quality, makes AI Analyst work with the OpenChamber /
OpenCode installation already on the PC, and turns the evidence package into a much more useful
investigation surface.

## Highlights

### AI Analyst without extra infrastructure

- New **OpenChamber / OpenCode** provider (`opencode://local`) uses the already signed-in OpenCode
  CLI in headless plan mode. No Ollama, LM Studio, extra API key or separate local server is needed.
- Default model: `opencode-go/deepseek-v4.1-flash`.
- OpenAI-compatible, OpenAI, Anthropic, DeepSeek, Z.ai and OpenCode Zen providers remain available.
- **Copy result** and **Copy all** export the complete finding as text.
- An indeterminate progress bar, elapsed seconds and **Cancel** show that the agent is working; the
  result panel returns to the top for a new finding.

### Evidence v2

The analyst now receives:

- process name, PID, parent PID/name and parent chain, including services hosted by `svchost.exe`;
- Authenticode signer status/subject, product and file version from the elevated service;
- sanitised and truncated command line (secret-like arguments are masked);
- observed duration, well-known remote port names and local host/subnet/gateway context;
- Axiom-owned firewall rule status instead of `Unknown`;
- an aggregated 30-day local flow baseline (first/last seen, flow-row counts, typical remotes).

The previous 5,000-row baseline truncation is gone; the baseline is aggregated in SQLite.

### Axiom Shield and alerts

- Remembered Shield decisions support **Block** and **Unblock** from a button or the right-click menu.
- Pending rows show the remote `IP:port`, trigger explanation and a clear "not a malware verdict" note.
- **The ask queue is durable.** A pending application remains listed after its connection ends until
  the user chooses Allow, Block or Dismiss; multiple pending applications stay visible. Dismiss hides
  the app until it opens a new connection. The alert banner and each row expose Allow/Block/Dismiss.
- Microsoft-signed processes are filtered with a visible count.
- Alerts navigate to Firewall, highlight the exact application and scroll to it.
- The bell keeps alert history even when notifications are off.

### Settings, privacy and window polish

- **Show notifications**, **Show tray icon** and **Hide background console windows (Node, PowerShell,
  Python)** are independent settings.
- The window hider follows only descendants of the Axiom desktop process, so unrelated programs with
  the same names are never touched. UAC and interactive third-party installers stay visible.
- Native resize cursors, drag resize, Win+arrow snap, edge snap, double-click maximize/restore,
  working caption buttons, 900×600 minimum and responsive status/Firewall layouts.
- Close-to-tray, start-minimized and clean `ShutdownRequested` handling.
- The product description is now **Free Open-Source Network & AI Agent Security** in the title bar,
  header, footer, shortcut and service description.
- The high-resolution lockup uses high-quality interpolation and an exact 3:1 aspect ratio for a
  crisp header.

### Optional DKG

- When the local DKG node is installed, Axiom starts it on launch if it is not already answering,
  verifies the supervisor/worker and `/api/status`, and never starts it in Standard mode.

## Known limitations

- ETW telemetry is not integrated yet. SNI, TLS certificate subjects, DNS query names, exact
  per-connection byte counts and TIME_WAIT ownership remain missing evidence.
- No reputation or threat-intelligence feed is configured; Axiom does not invent a score.
- Command lines are sanitised and truncated, and protected processes may not expose them.
- Axiom reports only its own firewall rules, not the effective Windows default policy.
- File hashes and full Authenticode chain details are not part of the evidence package.
- The locally built `Axiom.Service.exe` in this development release is unsigned; the analyst correctly
  reports it as unsigned.

## Upgrade notes

- Existing settings are preserved. The old `tray-notifications.txt` value is migrated to the new
  notification setting on first run.
- The Axiom service must be restarted after upgrading so the new process metadata and rule
  correlation are available. The installer handles this; a portable copy needs the service stopped
  and started once.
- No database migration is required for existing history; the baseline is computed from the existing
  flows table.

## Requirements

- Windows 10 x64 19041+ (Windows 11 x64 uses the same code path; Windows 11 VM validation is still in
  the test matrix).
- The published build is self-contained and needs no .NET runtime.
- Axiom Shield firewall writes and the service require the documented one-time administrator
  approval. The desktop UI stays unprivileged.
