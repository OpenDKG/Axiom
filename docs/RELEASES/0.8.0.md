# Axiom 0.8.0

**Release date:** 2026-11-08

Axiom 0.8.0 is the first release positioned as **Free Open-Source Network & AI Agent Security**. It
brings the Avalonia Windows UI to production quality, makes AI Analyst work with the OpenChamber /
OpenCode installation already on the PC, and turns the evidence package into a much more useful
investigation surface.

## Highlights

### AI Analyst without extra infrastructure

- New **OpenChamber / OpenCode** provider (`opencode://local`) uses the already signed-in OpenCode
  CLI in headless plan mode. No Ollama, LM Studio, extra API key or separate local server is needed.
- Default model: `opencode-go/deepseek-v4.1-flash`.
- OpenAI-compatible, OpenAI, Anthropic, DeepSeek, Z.ai and OpenCode Zen providers remain available.
- **Copy result** and **Copy all** export the complete finding as text.
- An indeterminate progress bar, elapsed seconds and **Cancel** show that the agent is working; the
  result panel returns to the top for a new finding.

### Evidence v2

The analyst now receives:

- process name, PID, parent PID/name and parent chain, including services hosted by `svchost.exe`;
- Authenticode signer status/subject, product and file version from the elevated service;
- sanitised and truncated command line (secret-like arguments are masked);
- observed duration, well-known remote port names and local host/subnet/gateway context;
- Axiom-owned firewall rule status instead of `Unknown`;
- an aggregated 30-day local flow baseline (first/last seen, flow-row counts, typical remotes).

The previous 5,000-row baseline truncation is gone; the baseline is aggregated in SQLite.

### Connections traffic view

- **Group by app** folds every socket of one executable into one row with its cumulative TCP
  megabytes sent and received, plus the **realtime rate** measured in the latest poll
  (`now ↑ … · ↓ …` or `now idle`). UDP-only applications say **traffic not measured** instead of
  showing an invented zero.
- An expanded application stays expanded across the one-second refresh; rows are updated in place
  instead of rebuilding the list. The sort field and **Ascending/Descending** control sit in the
  action toolbar next to Block/End task, not in the filter bar.
- Buttons now use the active Axiom palette instead of the Fluent grey default: surface background,
  themed border, accent hover/press, and the accent primary style on Apply/Analyze/Export/Shield
  actions. The same styles follow Dark, Light, Dark Midnight and Light Warm.
- Sort the groups by **Total traffic**, **Sent**, **Received**, **Sockets** or **Name**, then switch
  **Ascending/Descending** to put the heaviest consumer first. Groups without measurement stay at
  the end of the traffic sorts.
- Totals come from Windows extended TCP statistics enabled per connection by the elevated service.
  They start when Axiom first observes a connection, and flows shorter than one poll are not
  reconstructed.

### Axiom Shield and alerts

- **Agent sessions now include OpenCode/OpenChamber.** The Agents and Agent Stats session cards read
  Claude Code, Codex and OpenCode/OpenChamber metadata read-only. The OpenCode database is opened in
  SQLite read-only mode with `session_v2` rows; a session is **live** when its host process runs or
  its timestamp changed in the last five minutes. An active OpenCode session no longer appears as
  "not running", while older sessions remain labelled historical instead of erroring.

- Remembered Shield decisions support **Block** and **Unblock** from a button or the right-click menu.
- Pending rows show the remote `IP:port`, trigger explanation and a clear "not a malware verdict" note.
- **The ask queue is durable.** A pending application remains listed after its connection ends until
  the user chooses Allow, Block or Dismiss; multiple pending applications stay visible. Dismiss hides
  the app until it opens a new connection. The alert banner and each row expose Allow/Block/Dismiss.
- Microsoft-signed processes are filtered with a visible count.
- Alerts navigate to Firewall, highlight the exact application and scroll to it.
- The bell keeps alert history even when notifications are off.

### Privacy Shield

- Five license-labelled, HTTPS-only blocklist sources: HaGeZi Multi PRO and OISD Big (GPL-3.0),
  WindowsSpyBlocker (MIT), and The Block List Project Ads/Tracking (Unlicense). They are downloaded
  from upstream at runtime, not bundled; no separate approval is required beyond their licenses and
  attribution. Upstream terms are rechecked before updating.
- The blocked-query log is live (2-second refresh), shows the domain, category and requesting
  application when Windows exposes it, and offers **Allow** and **Block** actions. Allow adds a
  custom allowlist entry; Block removes it and adds a custom blocklist entry.
- **Resolver statistics now explain why they can read zero:** when the resolver is running but no
  adapter DNS points at it, the page says so and links the next step. The adapter row shows
  `127.0.0.1 · Privacy Shield` after the UAC helper changes it, including after an app restart.
- Installed-service settings and the compiled ruleset live in `%ProgramData%\Axiom\` and are copied
  once from the previous service profile, so a service reinstall no longer loses the enabled state
  or forces a source re-download. The blocked-query history stays in the service account's local
  profile because it is the only DNS data kept.
- Attribution is best-effort: Axiom maps the loopback UDP/TCP source port to the owning PID through
  the Windows owner tables. Protected or exited processes can appear as `unknown app`.

### Settings, privacy and window polish

- **Show notifications**, **Show tray icon** and **Hide background console windows (Node, PowerShell,
  Python)** are independent settings.
- The window hider follows only descendants of the Axiom desktop process, so unrelated programs with
  the same names are never touched. UAC and interactive third-party installers stay visible.
- Native resize cursors, drag resize, Win+arrow snap, edge snap, double-click maximize/restore,
  working caption buttons, 900×600 minimum and responsive status/Firewall layouts.
- Close-to-tray, start-minimized and clean `ShutdownRequested` handling.
- The product description is now **Free Open-Source Network & AI Agent Security** in the title bar,
  header, footer, shortcut and service description.
- The high-resolution lockup uses high-quality interpolation and an exact 3:1 aspect ratio for a
  crisp header.

### Installation profiles

- The setup now asks for **Complete installation (recommended)** or **Partial installation** and
  explains both before anything is written.
- **Complete** asks Windows once for elevation, registers and starts the Axiom service, then turns
  on every protection module: Axiom Shield with the `ask` policy, the Privacy Shield resolver
  (Balanced, all five sources downloaded and compiled up to the 500,000-entry local cap),
  notifications, tray icon, background-console hiding, start with Windows, Blackbox, DKG and the
  supported agent hooks. Windows-wide DNS filtering still needs the one-click
  **Point adapter at resolver** UAC step, because adapter changes are never silent.
- **Partial** installs only the desktop app, history service and monitor without administrator
  rights, service registration, firewall rules, DNS resolver, autostart or optional modules.
- The applied profile is recorded in `%LOCALAPPDATA%\Axiom\install-profile.json`. If elevation is
  declined, the installer says so and leaves complete defaults unapplied instead of pretending.

### Optional DKG

- When the local DKG node is installed, Axiom starts it on launch if it is not already answering,
  verifies the supervisor/worker and `/api/status`, and never starts it in Standard mode.

## Known limitations

- ETW telemetry is not integrated yet. SNI, TLS certificate subjects, DNS query names, exact
  per-connection byte counts and TIME_WAIT ownership remain missing evidence.
- No reputation or threat-intelligence feed is configured; Axiom does not invent a score.
- Command lines are sanitised and truncated, and protected processes may not expose them.
- Axiom reports only its own firewall rules, not the effective Windows default policy.
- Per-application traffic totals are TCP-only, start when the service first enables extended TCP
  statistics on a connection, and do not reconstruct flows shorter than the one-second poll. UDP
  traffic is labelled `traffic not measured`. The realtime rate is the delta of the latest poll, so
  bursts shorter than the poll interval may be undercounted.
- File hashes and full Authenticode chain details are not part of the evidence package.
- The locally built `Axiom.Service.exe` in this development release is unsigned; the analyst correctly
  reports it as unsigned.

## Upgrade notes

- Existing settings are preserved. The old `tray-notifications.txt` value is migrated to the new
  notification setting on first run.
- The Axiom service must be restarted after upgrading so the new process metadata and rule
  correlation are available. The installer handles this; a portable copy needs the service stopped
  and started once.
- Privacy Shield settings and compiled rules move from the service profile to
  `%ProgramData%\Axiom\` on the first service start. They are copied, not moved; the previous files
  are left in place. The blocked-query history stays where it was.
- No database migration is required for existing history; the baseline is computed from the existing
  flows table.

## Requirements

- Windows 10 x64 19041+ (Windows 11 x64 uses the same code path; Windows 11 VM validation is still in
  the test matrix).
- The published build is self-contained and needs no .NET runtime.
- Axiom Shield firewall writes and the service require the documented one-time administrator
  approval. The desktop UI stays unprivileged.
