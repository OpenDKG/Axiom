# Axiom 0.10.3

**Release date:** 2026-11-09

Makes the sharing feature work for how agents actually fetch: through tools. Includes the first
end-to-end proof that a report reaches the Blackbox community graph.

## Agent tool attribution

- An agent rarely opens a socket itself. It shells out to `curl`, `git`, `pip` or `nslookup`, so the
  DNS query belongs to the tool child and the previous rule (querying process must be an agent)
  almost never fired.
- Axiom now walks the parent chain of the querying process once per process (cached for 30 seconds,
  up to six levels) and records the nearest known agent ancestor on the blocked event.
- A malware-list domain requested by such a tool is a truthful `fetched-by-tool` sighting and enters
  the preview queue; the queue detail names both the tool and the agent, for example
  `Blocked for nslookup.exe via opencode.exe by the malware list.`
- A tool child with no agent ancestor stays local, as before.

## Live verification

With the adapter temporarily pointed at the Privacy Shield resolver:

1. An agent tool (`nslookup` under OpenCode) fetched a malware-list domain (`win.down.55kantu.com`).
2. Axiom queued a pending candidate automatically, attributed to `nslookup.exe via opencode.exe`.
3. The desktop submitted it while sharing was on, and the Blackbox reporter returned
   `Report shared with the community` with
   `urn:guardian:report:0xbca2ceb415db9cbb5be5e95734f112514af3216e:2b51940ba98e5a0d`.
4. `blackbox report --status` lists it in the community's shared memory:
   `stage: reported (monitor) — reported by unlisted authors only`.
5. Sharing was turned off again and the adapter returned to DHCP.

The stage is exactly what the corrected copy says: a community sighting, monitored until independent
nodes corroborate it; blocking remains in the curated verified tier.

## Interface

- The threat-sharing description now says an agent fetched the domain "directly or through a tool it
  ran (such as curl or git)", matching the new attribution.
