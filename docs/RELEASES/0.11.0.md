# Axiom 0.11.0

**Release date:** 2026-11-11

The public release line resumes above `0.10.25` after the short 0.2.0/0.3.0 reset. The application
code is the 0.3.0 code plus a release-ordering guard; there are no new runtime protection changes
in this version.

## Why 0.11.0

GitHub orders releases by semantic version, not creation time. The 0.2.0 and 0.3.0 releases were
therefore listed below the earlier 0.10.x releases and looked missing. `0.11.0` is greater than the
highest previous tag (`0.10.25`) and greater than the reset tags, so it appears at the top of the
release list. The 0.2.0/0.3.0 releases remain as historical snapshots.

`scripts/build-release.ps1` now reads existing `v*` tags and refuses to build a version that is not
greater than the highest one. Future releases therefore cannot be hidden by a lower version number.

## Included changes (rollup)

From 0.2.0:

- Public-list matches stay local; Privacy Shield no longer proposes them to Blackbox/DKG.
- Blocked events carry local matched-rule, source id/name/version, Axiom version, reason,
  `isListDerived`, `lookupBlocked` and timestamp provenance.
- AI Analyst suppresses list-derived indicators; unavailable provenance fails closed.

From 0.3.0:

- User-triggered **Check graph** on blocked rows: local Blackbox `/api/threat`, public/local/
  community tiers, 5-second bound, 10-minute/256-entry cache, explicit Unknown and no badges.
- Setup can upgrade while the registered Windows service is running; only a running desktop blocks
  Setup, and an interactive service copy in the install directory is stopped before copying.

## Compatibility and rollback

- `0.11.0` is greater than `0.10.25` and `0.3.0`; portable ZIP and Setup upgrade normally.
- The installed service image remains compatible; no service code changed between 0.2.0 and 0.11.0.
- Previous service backup: `%LOCALAPPDATA%\Axiom\service-backup-0.2.0.exe`.
- Store/MSIX package versions are separate and must not be republished with a lower package version.

## Verification

- `dotnet build Axiom.sln -c Release`: 0 warnings, 0 errors.
- `dotnet test Axiom.sln -c Release`: 574 passed, 0 failed.
- Desktop, service and Setup report `0.11.0`.
- Release-order guard rejects `0.3.0` after `0.10.25` and accepts `0.11.0`.
- Live host: desktop 0.3.0 was upgraded to 0.11.0 during release; service 0.2.0 remains running,
  adapter DNS `127.0.0.1, 192.168.0.1`. Check graph still reports Unknown rather than a false badge
  when the local dashboard has no per-IOC entry.
