# Axiom 0.10.24

**Release date:** 2026-11-11

The optional-module cards now describe the Start button that actually exists.

## What was wrong

When DKG was not running, the probe said "Axiom does not start it", and the Blackbox message said
"Axiom does not start it" as well. Both modules have a **Start** button on the Agents page, so the
status contradicted the UI (issue #230, last row).

## What changed

- DKG not-running and timeout details now say to press **Start** in Axiom or run `dkg start`.
- The Blackbox not-running detail says to press **Start** in Axiom or use its own launcher.
- No probe behaviour changed; only the detail strings and the test assertion.

The wider documentation drift in issue #230 was addressed by the documentation pass merged in
PR #240 (README, SECURITY_MODEL, THREAT_INTELLIGENCE, INTEGRATIONS and AI_ANALYST now describe
what can leave the machine, module control, credentials and threat sharing).

## Verification

- `dotnet build Axiom.sln -c Release`: 0 warnings, 0 errors.
- `dotnet test Axiom.sln -c Release`: 564 passed, 0 failed.
- No module was started or stopped during verification.
