# Axiom 0.51.0

**Released:** 15 November 2026

0.51.0 records the live verification of three more harnesses and adds template tests that keep
their generated hooks on the shared Axiom guard instead of the vendor-only path.

## Verified live in the lab

| Harness | Installed build | Generated 0.50.x hook |
| --- | --- | --- |
| Cline (hook-level; extension not installed) | 4/15 | **15/15** |
| GitHub Copilot CLI 1.0.112 | 4/15 | **15/15** |
| Cursor (hook-level; GUI not installed) | 4/15 | **15/15** |

Each hook was executed exactly as its host does: Cline `tool_call.input` + `cancel`, Copilot
`toolName/toolArgs` + `permissionDecision`, Cursor `tool_name/tool_input` + `permission`. Live
coverage is now OpenCode, Codex, Claude, Gemini, Cline, Copilot CLI, Cursor (**7/11**).

## What this adds

- `HarnessHookCoverageTests` (Presentation.Tests) assert that the Cline, Copilot and Cursor hook
  templates contain `_check_command_safety`, `_sensitive_store`, `_axiom_injection` and the correct
  deny shape (`cancel`, `permissionDecision`, `permission`).

## Known follow-up

The WPF `Axiom.UI.Services` copies of these three hook templates still carry the vendor-only body
(no shared guard); the Avalonia/Presentation templates are the ones verified here. Filed as issue
**#361** so the WPF copies are synced before any build that provisions hooks from that assembly.

## Verification

- `dotnet build Axiom.sln -c Release` — 0 warnings, 0 errors.
- `dotnet test Axiom.sln -c Release --no-build -m:1` — full suite in the release run.
- VM remains on 0.49.0; live checks used generated hooks from the branch.
