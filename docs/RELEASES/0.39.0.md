# Axiom 0.39.0

**Released:** 15 November 2026

0.39.0 implements the decision layer for F-19 part B: a pure, testable policy that turns a
process-creation observation into `Allow`, `Record` or `Block` before the service subscribes to
ETW/WMI and records or stops the child.

## What this adds

- `AgentProcessSpawnPolicy` (`src/Axiom.Core/Enforcement`):
  - an agent child that is an executable in `Downloads`, `AppData\Local\Temp`, `Windows\Temp` or
    `Users\Public` → **Block** ("agent spawned an executable from a download or staging folder");
  - any other agent child → **Record**;
  - an executable from a staging folder started by a non-agent parent → **Record**;
  - a known risky binary (`powershell`, `cmd`, `wscript`, `mshta`, `certutil`, `bitsadmin`,
    `wmic`, …) outside an agent session → **Record**;
  - exact allowlisted image paths → **Allow**;
  - unrelated children → **Allow**.
- Path matching is case-insensitive and accepts forward slashes; the policy has no I/O, so it is
  unit-tested with synthetic events.

## Verification

- 8 new tests in `AgentProcessSpawnPolicyTests` (staged exe, temp script, ordinary child,
  allowlist, unrelated parent, risky binary, case/slash variants, empty path).
- `dotnet build Axiom.sln -c Release` — 0 warnings, 0 errors.
- `dotnet test Axiom.sln -c Release --no-build -m:1` — full suite in the release run.
- **Live VM verification is pending install**; the ETW/WMI subscription that feeds this policy is
  the next F-19 step, not part of this release.

## Upgrade notes

Install over 0.38.0. No runtime behaviour change yet; the policy is not wired to the service.
