# Axiom 0.10.12

**Release date:** 2026-11-10

Two clarity fixes around agent detection and hook startup.

## Antigravity

- Google Antigravity is now recognised as an agent executable. It is surfaced first in the ask queue
  and the agent lockdown can cover it like other agents.
- It has **no hook integration**: Antigravity does not use the Claude/Codex-style hook protocol, so
  it produces no hook evidence and is not listed as a protected harness. The Agents page now says
  this explicitly instead of leaving its absence unexplained.
- Detection is name-based (`antigravity`), so a copy under another name is not covered by lockdown,
  same as the other agents.

## Hook startup order

- The stale-activity message now explains why a harness can look frozen: **an agent keeps the hook it
  loaded when it started**. If it started before Axiom wrote the hooks for a new build, it keeps the
  old plugin until it is restarted. Starting Axiom first, or restarting the agent after an Axiom
  update, restores reporting.
- Hook files live in the agent's own config directory and survive reboots; the order matters only
  when Axiom itself was updated.
- The Blackbox dashboard must also be running to receive audit events. The local
  `agent-evidence.jsonl` is written by the bridge even when the dashboard is down, but the Agents
  activity list reads the dashboard.

## Verification

- `dotnet build Axiom.sln -c Release`: 0 warnings, 0 errors.
- `dotnet test Axiom.sln -c Release`: 500 passed, 0 failed.
- Live check: after restarting OpenCode, `agent-evidence.jsonl` and the dashboard audit resumed and
  Axiom showed fresh events; before the restart the newest entry was 14:59 and Axiom reported its
  age in amber.
- Antigravity proxy detection covered by the agent-path test.
