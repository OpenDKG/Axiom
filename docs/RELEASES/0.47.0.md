# Axiom 0.47.0

**Released:** 15 November 2026

0.47.0 comes from the first **live Claude Code sweep**: Claude Code 2.1.325 was installed in the lab
VM after Codex, Axiom provisioned `~/.claude/settings.json`, and the same vector families were run
through the Claude hook.

## What the live sweep found

| Hook under test | Result |
| --- | --- |
| Installed 0.30.0 Claude hook | 4/15 (controls, literal `.ssh`, wallet keystore) |
| 0.46.0 generated Claude hook | 14/15 |
| 0.47.0 generated Claude hook | **15/15** |

Claude's `Read`/`Write` tools pass the file as **`file_path`**, not `path`/`filePath`. The 0.46.0
store check looked at `path`/`filePath` only, so `.git-credentials` was readable through Claude.

## Fix

- New `_arg_path(args)` in the shared guard returns the first non-empty of `path`, `filePath`,
  **`file_path`**; `_check_command_safety` uses it for the credential-store check.
- The OpenCode bridge store check also uses `_arg_path`, so a plugin payload that passes
  `file_path` is covered.
- The behavioural Python test adds a `file_path` store case.

## Verification

- Claude live vectors with the 0.47.0 generated hook: **15/15** (controls allow; `$HOME`, `\\?\`,
  move, takeown, upload, `reg save SAM`, procdump lsass, `sc create`, Register-ScheduledTask,
  `.git-credentials`, wallet keystore and injection all block).
- `dotnet build Axiom.sln -c Release` — 0 warnings, 0 errors.
- `dotnet test Axiom.sln -c Release --no-build -m:1` — full suite in the release run.

## Upgrade notes

Install over 0.46.0, then restart the desktop once so it reprovisions `~/.claude/settings.json` and
the shared hook script. Live verification on the installed build is still pending the owner's
upgrade.
