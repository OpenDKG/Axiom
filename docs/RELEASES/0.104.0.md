# Axiom 0.104.0

**Released:** 17 November 2026

## Apply a validated rule file, one confirmed step (FND-008 complete)

The import preview validates a file but could not create anything; applying meant retyping every
rule. Network Control now has **Apply imported**, which appears only after a preview with at least
one valid rule.

Safety stays explicit:

- One confirmation lists the rules (up to five with "… and N more"), says that only Axiom-owned
  rules change, and is marked destructive. Cancelling changes nothing.
- Writes use the same service command (`RuleApply`) and write gate as the rule editor; with Shield
  off or the gate closed the action refuses with a clear message.
- Each rule gets the Axiom identity for its application and direction, the imported scope, the
  current operator as creator and a description naming the source file. The file's own GUIDs are
  not trusted.
- Two rules for the same application and direction with different actions are a conflict; the whole
  import is refused so a silent block/allow flip cannot happen. Duplicates with the same action
  collapse into one rule.
- Failures are reported per rule after the attempt; the list refreshes.

## Verification

- `dotnet build Axiom.sln -c Release` — 0 warnings, 0 errors.
- New apply-plan tests: identity/dedupe, operator and source description, conflicting actions
  refused. Import/export test suites still pass.
- Installed in the VM; a mixed file produced one rule through the confirmation, visible in Owned
  rules afterwards.
- Windows CI build, tests and packaging check pass.

## Note

This completes FND-008's import/export pair. Applying a file still creates real Windows Firewall
rules; the confirmation and the write gate are the only safeguards by design.
