# Axiom 0.10.8

**Release date:** 2026-11-10

Axiom no longer turns every refresh into disk writes. Routine history now lives in memory and is
persisted in small batches, which cuts SSD wear on an idle desktop by roughly a thousand times.

## What was writing

- The history writer saved the full snapshot every **two seconds**, rewriting every flow row even
  when nothing about it had changed.
- Every short-lived connection created a new row because the local ephemeral port was part of the
  flow identity. A browser could add hundreds of rows per minute.
- Throughput buckets were written every ten seconds, blocked-query history opened the file for each
  blocked lookup, and retention ran hourly.

## What changed

- History persists the **stable** part of the snapshot: a connection must be present in two
  consecutive refreshes. Short-lived sockets no longer reach SQLite.
- The write cadence is **two minutes** instead of two seconds.
- Only **new or changed** flows are written. Unchanged flows refresh `last_seen` every **six hours**.
- Ephemeral local ports collapse into **one row per remote endpoint** (history is grouped by remote
  anyway). The local address is kept, the port is not.
- Throughput buckets are buffered and written as one transaction every **five minutes**.
- Blocked-query history is buffered in RAM and appended every **30 seconds**, and flushed on stop.
- Retention runs every **six hours**.
- Every pooled SQLite connection sets `synchronous=NORMAL`, `temp_store=MEMORY`, a larger cache and
  a higher checkpoint threshold; previously only the migration connection had those pragmas.
- The installer waits for a pending service stop and retries the image copy (exit code 7 fix).

## Measured

With the desktop closed, the service process accounted for:

| | Before | After |
|---|---|---|
| 30 s sample | 36.7 MB | ~37 KB |
| Sustained | ~1.2 MB/s | ~1.2 KB/s |
| Per day | >100 GB | ~0.1 GB |

The remaining writes are one small history batch every two minutes, one throughput batch every five
minutes, and the buffered blocked history. Queries and the live UI still use the same data; only the
persistence cadence changed.

## Trade-offs

- A connection is recorded after it survives one refresh cycle, so very short connections do not
  appear in persisted history (they still appear in the live snapshot).
- History rows show the local address without the ephemeral port.
- A crash can lose up to two minutes of history and up to 30 seconds of blocked-query history; the
  live lists and counters were already in memory only.
