# Axiom 0.10.6

**Release date:** 2026-11-10

The resolver keeps existing and working, but it can no longer take the network down when it stops
answering. Adapters pointed at Privacy Shield keep their previous DNS server as a fallback.

## Why

Pointing an adapter at the loopback resolver replaced its DNS list with `127.0.0.1` alone. If the
resolver stopped or stopped answering, that adapter had no other server to ask, so every name lookup
failed until someone restored the DNS by hand. That is what produced the LAN outage on 10 November.

## What changed

- **Resolver first, previous DNS behind it.** The UAC adapter helper now writes `127.0.0.1` followed
  by the adapter's earlier servers (`192.168.0.1` on the test LAN). If the resolver stops or hangs,
  Windows fails over to that server and names keep resolving.
- **No single-server adapters.** Only an address family with a real fallback is changed. With no
  previous IPv6 DNS, the helper leaves IPv6 alone instead of adding a dead `::1`.
- **Idempotent.** The fallback comes from the machine-distributed snapshot saved before the first
  change, so pointing the same adapter again does not stack `127.0.0.1` or forget the router.
- **Honest warning.** The Adapter DNS card keeps two states apart: no working DNS at all (forced
  alert), and a stopped resolver where the fallback still answers but filtering is bypassed
  (warning plus a normal alert).
- The 0.10.5 service failsafe is unchanged: on disable, service stop or a failed resolver start the
  service restores the saved DNS exactly, without an elevation prompt.

## Trade-off

The fallback keeps the connection alive by bypassing the filter: while the resolver is down, blocked
domains resolve through the router again. Axiom reports that state instead of pretending the shield
is active. Once the resolver answers, the first entry takes over again.

## Verification

- `dotnet build Axiom.sln`: 0 warnings, 0 errors.
- `dotnet test Axiom.sln`: 479 passed, 0 failed (11 new tests for the address plan and snapshot).
- Live check on the test machine: Ethernet 2 = `127.0.0.1, 192.168.0.1`; allowed names resolve,
  `doubleclick.net` and `google-analytics.com` return NXDOMAIN; internet reachable.
- Freeze test: the service process was suspended so the resolver stopped answering. `example.com`
  still resolved in 1.3 s through the router fallback, internet stayed reachable, and the blocked
  name resolved too - the honest bypass this release describes. After resuming, the blocked name
  returned NXDOMAIN again.
