# Axiom 0.10.6

**Release date:** 2026-11-10

An adapter pointed at the Privacy Shield resolver now keeps its previous DNS servers as a fallback,
so a stopped or unresponsive resolver degrades filtering instead of breaking name resolution.

## Why

Windows asks an adapter's DNS servers in order. Privacy Shield needs `127.0.0.1` first, but writing
that address alone leaves the adapter with no second server. If the resolver is stopped, restarted or
not answering, the lookup has nowhere else to go and name resolution fails until someone restores the
DNS by hand. A one-entry DNS list is a single point of failure for the whole machine.

## What changed

- **Resolver first, previous DNS behind it.** The UAC adapter helper now writes `127.0.0.1` followed
  by the servers that were on the adapter before (for example the router's `192.168.0.1`). If the
  resolver stops or hangs, Windows fails over to that server and names keep resolving.
- **No single-server adapters.** Only an address family with a real fallback is changed. With no
  previous IPv6 DNS, the helper leaves IPv6 alone instead of adding a dead `::1`.
- **Idempotent.** The fallback comes from the machine-distributed snapshot saved before the first
  change, so pointing the same adapter again does not stack `127.0.0.1` or forget the router.
- **Honest warning.** The Adapter DNS card keeps two states apart: no working DNS at all (forced
  alert), and a stopped resolver where the fallback still answers but filtering is bypassed
  (warning plus a normal alert).
- The 0.10.5 service failsafe is unchanged: on disable, service stop or a failed resolver start the
  service restores the saved DNS exactly, without an elevation prompt.

## Trade-off

The fallback keeps the connection alive by bypassing the filter: while the resolver is down, blocked
domains resolve through the second server again. Axiom reports that state instead of pretending the
shield is active. Once the resolver answers, the first entry takes over again.

## Verification

- `dotnet build Axiom.sln`: 0 warnings, 0 errors.
- `dotnet test Axiom.sln`: 479 passed, 0 failed (11 new tests for the address plan and snapshot).
- Live check: adapter DNS `127.0.0.1, 192.168.0.1`; allowed names resolve, `doubleclick.net` and
  `google-analytics.com` return NXDOMAIN, internet reachable.
- Failure test: with the resolver process suspended, `example.com` still resolved in about 1.3 s
  through the fallback and the connection stayed up; after resuming, the blocked name returned
  NXDOMAIN again.
