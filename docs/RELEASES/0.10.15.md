# Axiom 0.10.15

**Release date:** 2026-11-10

Privacy Shield now notices when a browser resolves names through its own DNS-over-HTTPS
provider, which skips the Axiom resolver and makes DNS blocking and counters look broken.

## Why

Privacy Shield is a DNS filter. It can only see a query that reaches `127.0.0.1`. Chrome, Edge
and Firefox can each be switched to secure DNS (DoH), and then their queries go straight to the
browser's provider: blocked domains still load and the resolver counter stays at zero, with
nothing on the page explaining why.

## What changed

- New read-only detector, `Axiom.Presentation.DohBypassDetector`, reads:
  - Chrome: `%LOCALAPPDATA%\Google\Chrome\User Data\<profile>\Preferences`,
  - Edge: `%LOCALAPPDATA%\Microsoft\Edge\User Data\<profile>\Preferences`,
  - Firefox: `%APPDATA%\Mozilla\Firefox\Profiles\<profile>\prefs.js`.
- Chrome/Edge count as a bypass when `dns_over_https.mode` is `secure`, or `automatic` with a
  custom template. Automatic without a template is not reported: it only upgrades a resolver the
  browser recognises, and the loopback resolver is not one.
- Firefox counts as a bypass when `network.trr.mode` is `2` (DoH first) or `3` (DoH only); `0` and
  `5` are off. The configured `network.trr.uri` is shown when present.
- The Privacy Shield page shows an amber warning above the adapter card, naming the browser and
  profile and where to turn secure DNS off (`chrome://settings/security`, `edge://settings/privacy`,
  Firefox Privacy & Security). When nothing is found it says so instead.
- The profile scan runs off the UI thread and at most once every 30 seconds. It never writes to a
  browser profile or to the registry.

## Limits

- Windows system DoH is not checked. It is configured per DNS server address, and an adapter that
  points at `127.0.0.1` has no DoH template; an adapter still on a public encrypted resolver would
  not show as pointed at Privacy Shield in the first place.
- Only the Chrome, Edge and Firefox profile files are read. Portable browsers, other Chromium
  builds and policy-driven secure DNS are not covered.
- Detection is a warning, not an enforcement: Axiom does not change browser settings.

## Verification

- `dotnet build Axiom.sln -c Release`: 0 warnings, 0 errors.
- `dotnet test Axiom.sln -c Release`: all tests pass; `Axiom.Presentation.Tests` 27 passed,
  including secure/automatic/off handling, Chrome + Edge, multiple profiles, Firefox modes 2/3
  versus 0/5, missing profiles and the warning text.
- Local machine: Chrome (Default, Profile 1) and Edge (Default) have no explicit
  `dns_over_https` entry, so the page reports no browser override.
