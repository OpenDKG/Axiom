# Axiom 0.10.4

**Release date:** 2026-11-09

Privacy Shield usability and a power-usage investigation, plus a documented Codex limitation.

## Privacy Shield

- **The live list is grouped and bounded.** Viber and similar apps can produce dozens of identical
  blocks a minute. Blocked queries now fold into one row per domain and app, showing the category,
  a count and the last time; the top six groups are shown by default, **Show all** expands to 40,
  and the list scrolls inside its card instead of growing the page.
- **Blocked query history is capped at 250 rows** and scrolls inside its own card. Allow/Block still
  act on the latest event of the group.
- **Adapter DNS moved above the lists.** The explicit UAC helper is now its own card directly under
  the resolver statistics, so it no longer sits below the blocking lists.

## Power usage

- Task Manager showed very high power usage. The cause was a long-running **Blackbox dashboard**
  process (`hermes.exe blackbox dashboard`, started at 12:19) busy-looping at roughly 200% CPU
  (about 5,600 CPU-seconds over 11 hours). Restarting that process returned it to idle, about 0% and
  85 MB. Axiom's own service stayed near 0% at idle in the same sample.
- Axiom's desktop stayed around 10% CPU in that sample; it polls the monitor and the agent pages on
  timers. Further reduction is possible but was not needed to explain the reported reading.

## Codex hooks on Windows

`codex exec` on this machine reports `hook: PreToolUse Failed` (and PostToolUse/Stop Failed) and never
executes the hook command, even with hooks trusted and `--dangerously-bypass-hook-trust`:

- the same command run manually or through `cmd /c` exits 0 and writes its evidence;
- a project-local hook that only appends to a marker file also fails and the marker never appears;
- Codex version tested: `codex-cli 0.167.0-alpha.3.2` on Windows.

Until that is fixed upstream, Axiom cannot audit Codex tool calls. OpenCode events work and resumed
after an OpenChamber restart.
