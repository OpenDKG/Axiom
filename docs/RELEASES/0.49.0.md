# Axiom 0.49.0

**Released:** 15 November 2026

0.49.0 fixes the slow, machine-freezing upgrade seen on 0.48.0, where a complete install copied
**8.3 GB / 116,903 files** for the upgrade backup (twice, because two setup instances ran), then
aborted at the end with "Optional setup stopped: a protected user-state change could not be restored".

## Fixes

- **Upgrade backup no longer copies regenerable multi-GB vendor data.** `UpgradeDataGuard` skips
  `oxigraph-data`, `node_modules`, `venv`, `.git`, `__pycache__`, `cache`, `*.log`, `*.tmp`, `*.etl`
  and any individual file above 32 MB. Findings, history, reporter key and DKG identity are still
  backed up; the backup drops from gigabytes to megabytes.
- **Setup is single-instance.** A named mutex refuses a second copy with a clear message, instead of
  each instance making its own multi-GB backup and fighting over the service.
- **User-state restore failures are warnings, not an install abort.** If protected
  MCP/model/favorite/session files cannot be restored while the desktop/DKG are running, the install
  continues and logs a WARNING to review them; the app and service are already upgraded at that
  point, so failing the whole setup was misleading.
- **Setup communicates duration and progress.** The Complete option says it can take 10-20 minutes
  and lists what is installed; every report line is timestamped with elapsed time so a long phase is
  visibly still running.

## Verification

- `dotnet build Axiom.sln -c Release` — 0 warnings, 0 errors.
- `dotnet test Axiom.sln -c Release --no-build -m:1` — **1082/1082**.
- New test: the guard keeps findings and the DKG identity while skipping oxigraph logs,
  node_modules, `daemon.log` and a 33 MB file.
- Live upgrade timing on the owner's machine is the real check; the fix targets the exact 8.3 GB
  backup seen in `upgrade-20261115-120646-*`.

## Upgrade notes

Install over 0.48.0. Existing multi-GB backups in `%LOCALAPPDATA%\Axiom\backups` are not deleted
automatically; remove the old/duplicate `upgrade-*` folders once the upgrade is confirmed.
