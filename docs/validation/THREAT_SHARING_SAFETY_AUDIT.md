# AXIOM 1.0 — Phase 6: Threat Sharing & Reporter Safety Audit

> **Scope:** Independent code and unit-test verification of Axiom's Blackbox threat-sharing pipeline (`ThreatShareController`, `ThreatShareWorker`, `ThreatShareVocabulary`, `ThreatShareIocExtractor`, `ThreatSharePreflight`, `ThreatShareCli`, and `UpgradeDataGuard`).

---

## 1. Safety Control Matrix

| Phase 6 Requirement | Code Implementation | Observed Behavior & Enforcement | Evidence / Tests |
|---|---|---|---|
| **No automatic community publication** | `src/Axiom.Service/ThreatShareWorker.cs`, `src/Axiom.Service/ThreatShareController.cs`, `src/Axiom.UI.Avalonia/AgentsPageViewModel.cs` | `ThreatShareWorker` only flushes `_incoming` requests to the local preview queue file. Submission (`SubmitThreatShareItemsAsync`) runs **only** when the operator clicks **Share** or **Send now** in the UI (`AgentsPageViewModel`), and `ThreatSharePreflight` enforces `sharingEnabled && consentPresent && reporterKeyPresent`. | `tests/Axiom.Service.Tests/ThreatShareTests.cs`, `ThreatSharePreflightTests.cs` |
| **No synthetic canaries, EICAR, test artifacts, or public-feed replays submitted as novel threats** | `ThreatSharePreflight.CategoryRefusal`, `ThreatSharePreflight.IsAlreadyKnown`, `ThreatShareVocabulary.EvaluatePublicationEligibility` | `SyntheticMarkers` (`eicar`, `canary`, `axiom-selftest`, `example.com/org/net`, `localhost`, `.test/.invalid/.localhost`), EICAR MD5/SHA-256 hashes (`SyntheticHashes`), known public resolvers, and values already present in `ruleset.json` are rejected locally before `hermes blackbox report`. `PublicFeedMatch` / `LocalObservation` stay `LocalOnly`; `ThreatShareController` has no entry point taking `PrivacyShieldBlockedEvent` (`Privacy_shield_list_detections_have_no_share_entry_point`). | `ThreatShareTests.cs`, `ThreatSharePreflightTests.cs` |
| **No automatic promotion of AI hypotheses to verified claims** | `ThreatShareIocExtractor.Extract`, `ThreatShareVocabulary.EvaluatePublicationEligibility` | AI Analyst findings only enter review if severity is `high`/`critical`, status is `SUSPICIOUS`/`SUPPORTED_ALERT`, `provenanceAvailable == true`, and the value was directly observed by Axiom (`WasObserved`, not only named in LLM prose). Uncorroborated `HeuristicOrAiSuspected` (`ProofGrade < Correlated`) stays `NeedsEvidence` (`AI_SUSPECTED_NEEDS_CORROBORATION`) and cannot publish. | `ThreatShareIocExtractorTests.cs`, `ThreatShareModels.cs` |
| **Strong provenance & safe indicator normalization** | `ThreatShareVocabulary.Normalize`, `ThreatShareCandidate.PublicPayloadPreview`, `ThreatShareCli.ReportAsync` | `Normalize` strips credentials (`user:pass@`), query strings, and fragments; rejects URL paths unless explicitly enabled; rejects non-domain file extensions (`.exe`, `.key`, `.pem`, `.json`, etc.); rejects RFC1918/loopback/CGNAT/link-local/TEST-NET/ULA/multicast IPs. Only `type=ioc`, `--ioc-type`, `--value`, `--context`, and `--severity` are passed to `hermes blackbox report` (`Detail` never leaves). | `tests/Axiom.Contracts.Tests/ThreatShareTests.cs` |
| **CDN & shared-hosting false-positive protection** | `ThreatSharePreflight.SharedHostSuffixes`, `ThreatShareVocabulary.SharedInfraIpv4Cidrs`, `TrackingHostSuffixes` | Bare multi-tenant CDN/Cloud IPs (`Cloudflare`, `Fastly`, `GitHub Pages`, `CloudFront`) receive `NeedsEvidence` (`NEVER_PROMOTE_SHARED_IP`). Subdomains and hosts on `github.io`, `github.com`, `githubusercontent.com`, `netlify.app`, `vercel.app`, `pages.dev`, `trycloudflare.com`, `azureedge.net`, `blob.core.windows.net`, `storage.googleapis.com`, and tracking/ad networks are refused locally in `ThreatSharePreflight`. | `ThreatSharePreflightTests.cs` (expanded with cloud object-store & CDN checks) |
| **No publication of credentials, private paths, prompts, or browsing history** | `ThreatShareIocExtractor`, `ThreatShareVocabulary.Normalize`, `ThreatShareCli.ReportAsync` | Free text, LLM prompts, Windows file paths (`NonDomainTlds`), session IDs, and query/fragment tokens are excluded both by normalization and by the fixed CLI argument schema in `ThreatShareCli`. | `ThreatShareTests.cs`, `ThreatShareIocExtractorTests.cs` |
| **Reporter identity survives upgrades & reinstalls** | `src/Axiom.Contracts/Blackbox/UpgradeDataGuard.cs`, `src/Axiom.Setup/SetupInstaller.cs` | `SetupInstaller` invokes `UpgradeDataGuard.Capture()` before running vendor installers and `UpgradeDataGuard.VerifyAndRestore()` afterward. It snapshots `hermes\blackbox`, `hermes\config.yaml`, top-level `Axiom` `.json/.jsonl/.db*` files, and all resolved DKG homes, restoring missing/0-byte files while preserving grown logs (retaining 3 timestamped backups). | `tests/Axiom.UI.Tests/UpgradeDataGuardTests.cs` |
| **Test environments isolated from production reporter identity** | `tests/Axiom.*.Tests/*` | All unit suites use temporary isolated directories or fake resolvers/clients; no test invokes `hermes blackbox report` against live production DKG or uses a production reporter key. | Reviewed test projects in `tests/` |
| **Retractions & rejected/ambiguous submissions accurately represented** | `ThreatShareState`, `ThreatShareCli.ReportAsync`, `ThreatShareController.RecordAsync`, `AgentsPageViewModel.RetractThreatShareItemAsync` | Explicit state separation across `Pending`, `Submitted`, `Rejected`, `Dismissed`, `Deferred` (exponential backoff, never dropped), `Unverified` (`UnknownOutcome` — never auto-retried to prevent duplicate reputational penalties), and `Retracted` (`Retract report` confirmation dialog noting CC0 replicas cannot be erased). | `tests/Axiom.Service.Tests/ThreatShareTests.cs`, `ThreatShareCliTests.cs` |
