# Claude Code review for Axiom

This integration enables **opt-in, read-only Claude audits** using the
official [Anthropic Claude Code GitHub Action](https://github.com/anthropics/claude-code-action).
It is intentionally not triggered on every commit to control model usage costs.

## Review locally

Clone the public repository and start Claude Code from the checkout:

```bash
git clone https://github.com/OpenDKG/Axiom.git
cd Axiom
claude
```

Ask for a read-only review with prioritized findings, source locations and suggested fixes.
Review any requested tool permissions before approving them.

## Automated GitHub Actions review

The opt-in workflow in this repository uses repository-managed Anthropic authentication.
A repository administrator configures that account independently of the person requesting a review.

## One-time setup (repository administrator)

1. Install the [official Claude GitHub App](https://github.com/apps/claude)
   and select **OpenDKG/Axiom**.
2. In OpenDKG/Axiom, open **Settings → Secrets and variables → Actions → New repository secret**.
   Configure **one** authentication method:
   - `ANTHROPIC_API_KEY`: paid Anthropic API key from Anthropic Console; or
   - `CLAUDE_CODE_OAUTH_TOKEN`: Claude Code OAuth token generated by
     `claude setup-token` for an eligible Claude Pro/Max account.
3. Verify the first run in the **Actions** tab and inspect Claude's response.

**Never paste credentials in the repository, issues, PR comments, or workflow files.**
An API key may incur Anthropic API charges; an OAuth token is subject to its
corresponding plan's eligibility and usage rules.

## Run a repository-wide audit

Open a GitHub issue in Axiom and add a comment (from a repository member with
write access):

```text
@claude Audit the Axiom repository for security vulnerabilities and correctness
bugs. Focus on firewall rules, privilege escalation, DNS, IPC, agent protection,
Blackbox, private telemetry and Avalonia portability. Prioritize actionable
findings with paths and lines. Do not modify any files.
```

Claude will respond in the issue. The action checks GitHub author permissions
for interactive requests.

## Review one pull request

Add a label named `claude-review` to the PR. The workflow runs on labeling,
and on subsequent commits while the label remains present. Remove the label
to stop future automatic re-reviews of that PR.

The workflow checks out and reviews only PR branches in this repository, not
untrusted fork PR heads. It does not grant Claude an instruction to modify
source code or merge a pull request.

## Scope and privacy

- The workflow requests read-only repository content access and write access
  for GitHub issue/PR comments, plus GitHub Actions status visibility.
- The **official Claude GitHub App** has its own installation permissions,
  which may be broader than this workflow. Review them before approving access.
- Claude sends relevant repository content to the model provider
  under your Anthropic account terms. Never store secrets or private local
  traffic captures in the Git repository.
- Feedback is advisory; run .NET tests, integration checks, Windows security
  validation and human code review before shipping.
- A workflow file alone does not connect an Anthropic account: installation
  and authentication above are mandatory.
